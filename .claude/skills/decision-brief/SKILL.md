# Decision Brief — 决策简报（拍板必配图）

核心立场：**"浅显"不是少给信息，而是同时给 话、表、图、数**。纯文字罗列选项不算简报；**缺件＝不合格**，不许发出去请拍板。

## 铁律

1. **永不使用** `AskUserQuestion` 及同类交互工具。所有疑问合并进简报，**一次往返**：证据看完后分析＋决策点＋选项一次给完，用户回一句短话即拍板执行；多个问题不连环追问。
2. 简报固定**四件套**（§2，顺序不许换）。小问题可缩短每项，不许缺件。
3. 没实测的数字一律 `(估)`；禁止编造精确数（"提升73.2%"）。关键数实测不了（缺环境/缺样本）→ 明写「此数未实测」，该点降级为**事实追问**（§4），**不请拍板**。
4. 只有**一个**推荐。禁止"都可以""视情况而定"。不推荐的选项也如实写好处。
5. 跨表达锁死：同一决策在所有后续输出中 A/B/C 编号、名称、顺序、推荐结论不变；改推荐须明说"我改推荐了，因为…"。
6. **未拍板＝不执行**：用户提问 ≠ 批准动手；推荐 ≠ 已批；没等到回复的决策点停在该点，其余已拍板的照常执行。用户说"你定吧"＝授权，直接拍板，只回一行"我选了 B，因为…；想换说一声"。
7. **审批档位**按可逆性：不可逆／代价高（动生产数据、部署、删除）须显式「可以／选A」才执行；可逆／轻量要"无异议即开工"，须宿主流程事先声明此档，本 skill 不自动给权。
8. 结尾永远是回复契约：`回复 A / B / C，或说"看不懂"换讲法、"full"要全量。`

## 1. 触发与编号

出现以下任一＝一个决策点；多个决策点按 ①②③ 编号逐点写，用户可逐点回或「都按推荐」：

- 多条可行修法，代价／影响面不同（取舍）
- 与既有 spec／规则／早前决定**冲突**（列选项让用户裁决，不自裁——冲突是升格信号，不是自裁依据）
- 范围、口径、阈值收不收
- 存量数据／残留处理不处理
- 可选加固项做不做
- 任何需要用户确认、澄清的分支

## 2. 四件套（颗粒度模板见 [references/brief-template.md](references/brief-template.md)，格式照抄）

| 件 | 内容 | 硬标准 |
|---|---|---|
| 选项块 | 每选项【选项A】≤4 行：短名字／人话一句(≤25字无术语，"哪个样本的哪一处"式)／**数字影响面**(本轮实测，未实测→(估))／好处·代价·可逆性 | 不拿模块名代替；砍到 2–3 个真实项，排除的一行"顺带排除：X，因为…"，不许稻草人；好处代价写对用户的效果不写实现细节 |
| 对比表 | 全份简报唯一一张：行＝维度(标 高好/低好)，列＝选项 | 格子必须是数字或具体后果(标 估/实测)，"较好/更快"不合格；每行 ◀ 最优；"综合"行与【推荐】一致 |
| 图 | 按决策形态五型选一（§3），每选项至少一张 | 靶子用当前任务真实数据，给全值或 `id＋前60字` 可复核 |
| 收尾 | 【推荐】＋一句话理由(对准用户目标) ＋ 翻转条件("更看重Y就选A") ＋ 【回复格式】契约 | 与对比表"综合"行一致；每个决策点自带一套，多决策点可「都按推荐」 |

## 3. 图型选型：按决策形态配图

| 决策形态 | 图 | 画法 |
|---|---|---|
| 多修法取舍（默认） | **分叉图** | 现状 → ◀决策点▶ → 每选项终点＝可感知后果("850ms(估)")；``` 内 ≤70列，只用开放连接线（CJK 陷阱见模板） |
| 口径收不收／某形态允不允许 | **前后对比** | 同一靶子：现值(实测全文) vs 收紧后 vs 放开后，两三栏竖排 |
| 改哪一步／哪一层 | **点线关卡** | 数据从产生到终态逐关卡一行：●放行 ○空转 ✂拦截 ★＝本方案改动处；末端标 终态 ✓/✗ |
| 存量处理不处理 | **覆盖漏斗** | `全量 N → 命中 M → 方案X后剩 K`，数字全部实测，残留给可定位名单 |
| 修法行为差异（用户是开发者） | **并排路径＋伪代码** | 每方案一条编号路径 ≤5 步；差异给 ≤10 行伪代码，注释标改动行 |

术语纪律：内部编号、闸门名、代号**只许出现在图内**；图外一律翻译成人话（"被复核闸门拦下"→"程序复核觉得删过头了，把值恢复了"）。选项描述超 60 字拆两行 bullet。

## 4. 按决策重量自动伸缩（拿不准就升一级）

| 级别 | 特征 | 做法 |
|---|---|---|
| 微 | 二选一、10分钟可改 | 四件套迷你版（表3行、图只画分叉） |
| 标准 | 影响实现、可逆、数天内 | 四件套完整 |
| 重大 | 架构/跨模块/不可逆/花钱/动数据 | 四件套＋时间链图(现在→选→6个月后)＋Before/After 差值表 |

事实类追问（不请拍板也要有结构）：`我目前理解：…（复述）／卡住我的是：…（唯一缺口）／为什么必须问：…（缺了会走A路 vs B路）`。一句话能答。

## 5. 风格按情况选（模型自主判断，不是阶梯）

四件套是底线；底线之上按情况取用，目标是让用户最快看懂，不是机械加码：

| 情况 | 选法 |
|---|---|
| 用户非技术 / 概念抽象 | 上**场景故事**；数字换成可感体验（"等8秒"而非"高延迟"） |
| 用户是开发者 / 性能与成本决策 | 上**同输入三路样本** + 最小**代码段** + Before/After **差值** |
| 维度≥3 且选项≥3，或用户要可视化 | 出**单文件 HTML 网页**（模板 rules 见下） |
| 用户说"看不懂" | **换一种表达**（故事↔表↔图↔网页），不在原文上再加一层 |
| 用户说"full / 详细说说" | 一次给全：故事+表+图+样本+代码 |

网页产出：`docs/decisions/decision-<yyyymmdd>-<slug>.html`，从
[references/templates/decision-page.html](references/templates/decision-page.html) 改数据（**配色结构勿改**，已过色盲/对比度校验），
回复路径＋打开命令（Win: `start "" "<path>"`；Linux/mac: `open`/`xdg-open`），聊天里仍留文字版四件套。
连续两次"看不懂"→ 停止加码，改问事实追问："你卡在**选项**，还是卡在**问题前提**？"

## 6. 发出前自检（逐决策点核对，任一不过就回炉）

- [ ] 四件套齐：每选项有人话+数字+可逆性；表带 ◀ 且标 估/实测；有图且靶子真实可复核
- [ ] 唯一推荐与对比表"综合"行一致；有翻转条件
- [ ] 冲突点列成选项未自裁；术语未泄漏到图外
- [ ] 一次往返：本轮所有决策点都已在这份回复里；结尾有回复契约
- [ ] 数字全部本轮实测或已标(估)；不可逆项停在待批状态
