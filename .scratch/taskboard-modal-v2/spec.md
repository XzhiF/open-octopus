# Spec: 任务看板弹窗 v2 — 统一壳 · 变更 · 对话接管 · 修复轮

> Tracker label: `ready-for-agent`
> 原型（primary source）：`packages/web-app/public/prototype/taskboard-v2.html`（v3 全交互，Playwright 回归通过）
> 词表：GLOSSARY-MAP 词条 Round / 修复轮 / 快速修改 / 人工接管 / 验收台账 / task-doer
> 决策：ADR-0024（打回单路径，amends ADR-0018 §5）、ADR-0025（task-doer 分身与会话两面性）

## Problem Statement

1. 任务在**执行中**时看不到"改了什么"——想中途了解现场，只能干等本轮跑完进验收台。
2. **待验收**时只有"打回→触发新工作流"一条反馈路径：改一个按钮圆角也要重跑整轮，成本高到让人放弃小改。
3. 执行中与待验收是**两个繁杂的弹窗**：长得像却各有一份，信息密度高、看不清重点，8 个动作按钮挤在标题栏里造成误操作。

## Solution

把两类弹窗合并为**一个任务控制台壳**，四个一级页签按状态装配：

- **💬 对话**（待验收/接管的默认页签）——由新内置分身 **task-doer** 承接，说话即改执行工作区代码（快速修改）；大改动 task-doer 劝退转修复轮。
- **≡ 变更**（执行中默认页签）——GitHub Files-changed 式文件列表 + unified diff + 提交/行数统计，数据复用既有 round-diff 契约，执行中即持续可见。
- **◆ 节点**（仅执行中）——绑定工作流节点的任务清单视图（状态/类型/用时/成本 + 节点事件），只读 + 深链执行详情。
- **✓ 走查 / ▶ 控制台·日志**——验收剧本走查置顶**启动 Runbook**（照单跑实物）；日志为轮次执行流水（含 ⚑ 人工干预高亮行）。

执行中遇到问题走**三分支**（右栏「✋ 有问题」）：① 暂停→注入干预→恢复（复用既有 pause/resume 端点）；② **人工接管**=abort 绑定执行、整屏对话一步一交、确认后带 takeover 标记进验收；③ 派 **task-fix 修复轮**。待验收侧：**打回单路径化**——打回一律产生修复轮（task-fix），绑定工作流不再重跑；快改每改即 commit、验收台账把人工干预/快速修改/takeover 分列留痕。

## User Stories

1. 作为执行人，我想执行中与待验收打开同一个弹窗壳，以便不用维护两套肌肉记忆。
2. 作为执行人，我想弹窗顶栏只有标题、状态 pill、用时/成本/commits 元信息和 全屏/关闭，以便不再误点装饰性按钮。
3. 作为用户，我想弹窗标题栏不再有红黄蓝"红绿灯"圆点，以便消除"总以为可以点"的误操作错觉。
4. 作为用户，我想用 ←/→ 切换页签、Esc 逐层关窗（对话框→弹窗），以便键盘流操作。
5. 作为执行人，我想执行中就有「≡ 变更」页签，以便随时看到本轮改了哪些文件。
6. 作为执行人，我想变更页签顶部有提交数/文件数/+行/−行/harness 干预/成本统计条，以便一眼掌握量级。
7. 作为执行人，我想点击文件行就地展开 GitHub 式 unified diff（行号、@@ hunk、加绿删红），以便不出窗看细节。
8. 作为执行人，我想在「本轮 / 累计」两个口径间切换，以便区分本 Round 产物与任务全程变化。
9. 作为执行人，我想执行中变更数据滞后不超过 10 秒（事件驱动+节流轮询），以便低成本地"半实时"。
10. 作为执行人，我想在「◆ 节点」页签看到绑定工作流每个节点的状态（✓/●/⏸/○/⏹）、类型（Agent/Bash/Loop/Swarm/Approval）、用时与成本，以便知道跑到哪了。
11. 作为执行人，我想展开节点行看它的执行事件（含该节点收到过的干预），以便定位卡点。
12. 作为执行人，我想从节点页签深链到既有的工作流执行详情视图，以便需要手术式操作（重试/重置）时去修复面，而不是在任务弹窗里。
13. 作为执行人，我想点「⏸ 暂停」挂起当前节点，随后「▶ 恢复」时弹出干预输入框，以便给偏航的 agent 指路而不杀轮次。
14. 作为执行人，我想干预框有「取消（保持暂停）」，以便反悔时不改变任何状态。
15. 作为执行人，我想注入的干预以高亮行（⚑ 人工干预 + 目标节点 + 原文）进入日志，以便事后回放谁在什么时候改了方向。
16. 作为执行人，我想右栏 LIVE 卡累计显示当前节点的干预次数，以便感知人工介入度。
17. 作为执行人，我想执行中弹窗默认不出现任何输入框（不打扰模式），以便干预只能经「⏸→注入」或「✋ 有问题」两个正式入口发生。
18. 作为执行人，我想点「✋ 有问题」打开三分支决策框（含已跑时长/成本/当前节点上下文 + 一个可选指令输入框），以便一次决定本 Round 去向。
19. 作为执行人，我想选「② 停流接管」时绑定执行被直接 abort（节点终止、工作区现场保留、不可回原流），以便干净地换人掌舵。
20. 作为执行人，我想接管后获得草稿同款的整屏「💬 对话接管」页签，agent 每句话直接改工作区代码、一步一交。
21. 作为执行人，我想接管中每次改动实时出现在「≡ 变更」（💬chat 徽标 + 统计同步），以便随时看实物。
22. 作为执行人，我想接管完成后点「✓ 确认本 Round 交付 · 转待验收」，产物带 takeover 标记进入验收 Gate（哪怕把关的还是我）。
23. 作为执行人，我想接管后仍可反手「改派 task-fix 通用流」收拾残局，以便接管到一半发现活不适合对话干。
24. 作为执行人，我想在接管件验收时看到"自动复检：未跑（接管件）"如实标注且**不被机器闸拦**，以便人工走查+跑起来看自行把关。
25. 作为执行人，我想选「③ 派 task-fix」时必须填指令，派发后进入修复轮：绑定流 abort、以指令驱动 task-fix（解析→开发/修复→回归→调整·补产物→自动交付），节点页签实时推进。
26. 作为执行人，我想修复轮自动完成后回到待验收且产物（round 报告/证据）已补齐，以便验收材料不因走轻路而缺席。
27. 作为执行人，我想修复轮期间在对话里说的话作为追加指令（经暂停→注入通道）生效，以便修复跑偏时能再纠。
28. 作为审阅人，我想待验收弹窗默认落在「💬 对话」页签，以便进门就能开说。
29. 作为审阅人，我想小改（按钮/文案/颜色/间距等）在对话里说一声就被改到执行分支并自动 commit（每改即提交），以便验收前顺手收尾。
30. 作为审阅人，我想快改在「≡ 变更」里带 💬chat 徽标、且台账把快改与轮次产物分列，以便区分 agent 产物与人工手改。
31. 作为审阅人，当我提出大改动时，我想 task-doer 用模型判断并劝退（给出「打回·派修复轮」按钮并把我的话整理成指令草稿带进打回框），以便对话不无限蔓延。
32. 作为审阅人，我想「✓ 走查」页签第一块是启动 Runbook（N 步 命令→预期，接既有预览/启动信道，「▶ 跑」可执行），以便照单看实物而非读汇报。
33. 作为审阅人，我想走查保持既有剧本门与 AC 核对（✗ 仍硬拦通过），快改数/干预数/takeover 标记出现在通过前的台账预览里，以便决策时看全人工介入度。
34. 作为审阅人，我想打回框不再有"修订重跑/轻量修复"二选一——写反馈即派修复轮（反馈落 fix-feedback 文件、驱动 task-fix），以便小反馈小成本。
35. 作为审阅人，我想打回反馈为空时被拒绝提交，以便修复轮永远拿到有效指令。
36. 作为后续开发者，我想一个 task 的执行/验收对话固定一条 task-doer 会话（懒建、跨 round 延续、任务字段指向），以便上下文记忆连续、无会话裂变。
37. 作为管理员，我想 task-doer 是登记在册的内置分身（persona + 技能族 + 目录结构随 setup 落位），以便身份可审计、与 task-author 写权环互不侵犯。
38. 作为平台维护者，我想对话消息 API 只暴露一个任务级入口（server 侧解析会话归属并注入任务上下文），以便对话行为可在 API 层完整测试。
39. 作为任务负责人，我想有「▤ 消耗」页签看到总计/按模型/分轮账本的完整 token 账（K/M 记数），以便不看日志就能核对 AI 用量与成本。
40. 作为任务负责人，我想有「▣ 产物」页签列出 spec/票/报告/证据/台账的分组文件清单，以便不进工作区目录也能取交付物。
41. 作为任务负责人，我想待验收弹窗最右栏「打回」下方有「■ 中止」、且走查内容不再嵌重复内列，以便所有动作一个地方找齐、页面不繁杂。

## Implementation Decisions

**分层原则**：engine 零改动（pause/resume(intervention)/retry-from/abort/task-fix dispatch 全部现成）；server 承载全部新行为；web 只呈现。测试 seam：S1 新（任务级对话 API）+ S2-S4 改/接线既有 + S5 E2E，浏览器不承担对话行为测试。

- **新增内置分身 task-doer（ADR-0025）**：`builtin-clones` 登记 + persona（定位："接住 task-author 谈好的一切，在执行与验收期按人指令直接动执行分支"）+ 技能族最小集（工作区编辑、验证）。会话跑在 **workspace-chat 通道**（cwd=任务执行 workspace），不解除 task-home guard 任何语义。内置分身数量词条随实现更新。
- **S1 任务对话 API（唯一新 seam）**：`GET /api/tasks/:id/chat` 取得或懒建 task-doer 会话（任务表新增可空字段指向该会话，如 `doer_session_id`）；`POST /api/tasks/:id/chat/messages`（SSE 回复）由 server 转发到 ws-chat 并注入任务上下文：当前 phase/round、batch 目录、spec 家族文件、启动 Runbook、写纪律（大改劝退规则在 persona/skills 里，不做关键词正则）。三种形态（快改/接管/修复轮追加指令）全走此口。
- **打回单路径（ADR-0024）**：acceptance 请求 schema 删除 `next_flow` 枚举；rejected 分支恒定走既有 fix 路由（workflow_chain 级 override 派 built-in/task-fix，server 合成 inputs：spec 目录/反馈文件/产物目录）。K16（信封 phases[] 冻结）不动。反馈必填校验从"rejected 需 feedback"扩为"即 task-fix 指令"。
- **接管 = 服务端聚合动作**：新增 task 级 takeover 端点，原子完成：abort 绑定执行 → 标记执行与台账（takeover、现场快照时间点）→ 确保 doer 会话就绪。不留 paused 半程。接管交付复用 acceptance 通道产物侧写（decision=accepted/rejected 不变，takeover 只是来源标记），台账如实"自动复检未跑（接管件）"，**不加新机器闸**。
- **干预接线**：⏸/▶ 直连既有 tasks pause/resume(intervention) 端点；恢复框取消=纯前端关窗。干预记录进执行事件流（既有 intervention.jsonl/agent_events），日志页签渲染高亮行；台账"人工干预 N 次 + 摘要"与 harness 干预计数并列。
- **快改提交语义**：task-doer 每完成一次有效编辑即在执行分支落 commit（提交信息含 quick-edit 标记）；round-diff 证据快照发生在决策时（ADR-0022 既有），故决策前快改自动被实物覆盖；台账"快速修改 ×N"分列（来源=提交标记统计）。
- **统一壳**：合并既有 simple-execution/done/terminal 三模式为一个 console 壳；验收台降级为壳内「走查」页签（剧本/复检/预览/instances 组件复用，打回框重做为单输入）；composite 与 authoring 两模式**不动**。页签装配（来自原型状态表）：

  | 状态 | 页签 | 默认 | 右栏 |
  |---|---|---|---|
  | running(flow) | 变更 · 节点 · 消耗 · 产物 · 控制台(事件流) | 变更 | Pipeline+LIVE 卡+（✋/⏸/■） |
  | paused | 同上 | 保持 | （▶恢复·注入/■） |
  | takeover | 对话接管 · 变更 · 节点 · 消耗 · 产物 · 日志(事件流) | 对话 | 进度+（确认交付/改派/■） |
  | fixing(修复轮) | 追加指令(chat) · 变更 · 节点 · 消耗 · 产物 · 控制台(事件流) | 节点（自动推进直播） | 进度+产物列 |
  | awaiting_review | 对话 · 变更 · 走查 · 消耗 · 产物 · 日志(事件流) | 对话 | 验收进度+（通过/打回/中止） |

- **⑩ 真机走查回补（原型定稿后追加）**：一、走查页签内容区**不得**再嵌「摘要+动作/验收进度」内列（AcceptanceSurface 的自带右栏在壳内渲染路径剔除），其中「■ 中止」并入壳最右栏动作区、落「打回」下方，复用既有任务级中止动作，不新增状态；二、日志/控制台页签内容 = 绑定执行的**工作区事件流**（agent_events 时间正序：工具/编辑/成败分类行 + ⚑ 人工干预粉色高亮行，SSE 实时追加），「任务 AI 消耗」卡从此页签迁出；**2026-10-09 用户终裁追加**：页签内旧 Phase/Report 叠面（发射门禁/R1 交付报告/轮次账本/盘上文件/大事报）**整体撤场、不另找落点**，控制台页签=纯事件流（原型 consoleHtml 形态），组件若无其它挂载点随票删除；三、新增 **▤ 消耗** 页签 = 既有 TaskAiUsageCard（总计/按模型/分轮账本，K/M 记数，⇕ 一键全展开）升格挂载 + 按会话/节点明细（节点 usage 汇总逐行 + task-doer 对话单独一行，两账不混，ADR-0025 口径）；四、新增 **▣ 产物** 页签 = 只读薄端点按约定目录返回分组清单（需求票面/报告证据/验收台账/原型），路径限定工作区内（遍历守卫），预览/复制；五、**⑪ 真机复点收口（2026-10-09）**：走查/日志页签内容底色与壳统一**净黑**（去内嵌浅底 card）；日志流**铺满到底**且新事件自动贴底跟随；待验收最右栏动作定版四枚、顺序逐字 =「✓ 验收通过」→「↩ 反馈打回 · task-fix 修复轮」→「🗂 工作空间」（当前 Phase 执行视图深链，target=_blank 新标签）→「■ 中止任务」；此四钮仅限待验收形态，执行中/接管/修复轮右栏不动。

- **变更页签**：数据 = 既有 round-diff 契约（repos/groups/files + numstat + 按文件 patch 懒取），本轮/累计口径既有；刷新 = SSE 任务事件（task_execution / artifacts / verify 等既有类型）触发 + 节流轮询 ≤10s，无新增事件类型。
- **节点页签**：数据 = 既有执行详情/节点事件读取端点；只读渲染 + 深链工作流执行视图；abort/takeover/fixing 各态的节点符号（⏹/⏸/推进中）由前端按执行状态推导。
- **Runbook 走查置顶**：读既有 spec-field 双层解析（runbook ① / legacy preview 合成 ②），"▶ 跑"接既有 preview start/stop；既有可编辑抽屉保留不迁。
- **shared schema 变更**：Task 增 doer_session_id 可空字段；acceptance body 删 next_flow；台账 payload 增 快速修改数 / 人工干预数 / takeover 标记。
- **UI 皮肤**：色板/字体/边框语言 1:1 沿用现 globals.css（净黑 TUI），新增语义色仅 takeover=pink、fixing=cyan、干预高亮=pink 行。

## Testing Decisions

- 好测试 = 只测对外行为：状态码、payload 字段、DB 行、台账文件内容、SSE 事件、E2E 可见结果；不测内部函数调用次序。防自证（expected 来自独立事实，遵守词表 Tautological Test 条）。
- **S1 对话 API（新测试集中地）**：懒建幂等、上下文注入（spec/反馈在 prompt 组装证据里可见）、快改产生 commit、修复轮期间消息=追加指令路由正确、多任务隔离。先例：clone/chat 路由既有集成测试。
- **S2 acceptance**：rejected→恒派 task-fix（断言 workflow_chain override 与合成 inputs）、next_flow 字段不再被接受、反馈必填、接管交付标记、台账分列断言（文件内容级，先例：round-evidence 服务既有测试）。
- **S3 pause/resume/干预**：resume(intervention) 端到端可达（薄接线，沿用 ExecutionLifecycle 既有测试面）。
- **task-doer 注册**：内置分身装载/目录白名单/setup 落位断言（先例：built-in clones 既有测试；数量断言随之更新）。
- **S5 E2E（e2e-harness 库）**：窄而全——执行中弹窗见变更统计；对话发一句→变更列表出现 💬chat 行；⏸→注入→日志见 ⚑ 行；接管→交付→待验收台账含 takeover；打回→修复轮节点推进→自动回待验收。UI 细节（皮肤/字号）不设断言。
- engine 包不加测试（零改动）。

## Out of Scope

- composite（多 phase DAG 总览）迁入统一壳——保持独立视图（Q7）。
- 不暂停的即时干预注入（RepairService live 路径已存在但不接 UI；后续增强）。
- 节点级操作（重试/重置/VarPool 手术）——留在 workflow-ops/repair 面。
- 启动 Runbook 写入口迁移/重做（authoring 侧闭环不动，验收台保留既有可编辑抽屉）。
- 解除或改造 task-home buildPathGuard 写权环。
- 草稿（authoring）弹窗的对话 UI 改版。
- 旧 harness chatbot 的干预通路改造（两条路并存）。
- 看板布局/列结构/卡片改版、全局皮肤变更、移动端。
