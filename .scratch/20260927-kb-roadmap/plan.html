实现计划：P-1 加七个阶段，判据不过就不进下一关

产能假设 1 人 + agent。总时长约 15–18 周（P1 迁移取 3 周下限、P2/P3 尾部并行可压到 ~14 周；取 5 周上限则是 18）。其中 P1 单引擎迁移是这一版新长出来的 3–5 周——它不属于知识体系本身，而是用一次性成本买断「跨引擎」这一整类问题。前 4 周（P0 + P1 起）就能让「写了能读」成立，且平台已经站在一座库上。

1阶段依赖与关键路径

关键路径：P0 → P1 → P2 → P4。虚线是唯一的真并行机会：P3 血肉与 P2 地图尾部可并行（不同子系统：P2 是采集与算子，P3 是经验契约与抽取编排）。竖虚线（第 6 周末）是整个计划的硬边界：它左边是「平台的地基」，右边才是「知识体系」；越线之前不许开任何知识分区的功能开发，否则等于在还没干的地面上刷漆。P6 排最后不是因为它不重要，而是它需要 P0–P5 攒出的 case 集——没有回归语料的评估台是空转，这是评审砍掉我原方案「进化门全家桶前置」的直接原因。

2逐阶段规划

P-1前提盘点 · 半天（写代码之前）

先证明这套体系的 ROI 假设成立

整套方案的隐含前提是任务分布会重复。这个前提从没被检验过，而断路 1（归因）与断路 2（漏报）会让「它其实没转」这件事看不出来。所以先花半天量一次。

交付物量验收
翻过去 6 个月的归档与草稿，人工分类：与之前某个任务「同类」的占比（同类 = 同一业务动作换对象，或同一批仓库反复联调）S一个百分比 + 20 行样本清单
同批样本量第二件事：跨仓任务占比（一次任务实际改动 ≥2 个仓库）S第二个百分比
判据（是「继续 / 不继续」的判据，不是「做好」的判据）：同类占比 < 30% → 本方案收益假设不成立，正确产品退化为「更好的检索 + 更好的归档」，P1 那 3–5 周不该为它做；跨仓占比 < 15% → 拓扑层整块降级为仓库登记表，P2 的采集器与 7 个算子不立项。
P0止血 · 1 周

先让「写了能读、错了会停」成立

目标：不新增任何能力，只把已有的假闭环打断并接成真链路。这一阶段结束时，系统第一次「归档产出的东西自己能用到」。在单引擎方案下，P0 还多了一条职责：它是 P1 迁移的前置门——166 文件的重构必须在「类型系统真的能报错」的环境里做。

交付物量验收
tsc --noEmit ratchet 基线进 CI（当前 690，只减不增）；构建别再走 tsup 全绕；同时开启 no-floating-promisesSCI 上基线文件 + 超标即红；漏 await 立刻红（这是 P1 的探测器）
修 archiveWorkspace 双定义：删/改名死方法，把 :130 事务版复活为删除路径专用STS2393 归零
调用方改 if (!result.success) throw + 补旧路径测试（现 archive-service.test.ts:147-236 全按新签名调，旧路径零覆盖）S「归档失败 → 不删数据」有测试
merger 改 append-only 保 id；org 经验写进 listAllRules 可扫目录；LLM 返回空不得静默 continueM归档→注入端到端断言
系统 agent 加第一个读工具 recall()（先只走 BM25，jieba 预分词）M30 条中文双字查询命中 > 0
swarm / loop / sub-workflow / hook 注入接线补齐M四类节点各一条注入生效测试
退出判据：中文双字回归集命中 > 0 · 归档产出可被注入器读到 · 归档失败不删数据 · CI tsc 基线不再涨。四条全绿才开 P1。

本阶段明确不做：新表、新服务、embedding、图。

P1单引擎迁移 · 3–5 周

SQLite 退场，全平台落到一座 ParadeDB 上

目标：不是「加一个知识库」，是把地基换成一座库，从而让后面所有阶段的跨区查询免费。这一阶段不新增任何面向用户的能力——它的验收是「功能一模一样地活着，但只有一座库」。这是本计划风险最高的一段，所以它的判据全是「没变坏」而不是「变好了」。

交付物量验收
ParadeDB(PG18) 容器 + docker-compose + --shm-size≥1g（实测 HNSW 会炸默认 64MB shm）+ pg_dump 备份与恢复演练S一条命令起；演练过一次恢复，没演练的备份不算备份
驱动选型（倾向 postgres.js： tuned for 少连接、tagged template、原生 jsonb）+ 连接池与 statement_timeout、idle_in_transaction_session_timeoutS池占用与队列深度进 actuator 指标
BaseDAO 异步化：25 个 DAO、542 处 this.stmt()、166 个文件的调用点改 await；分批推进：先叶子 DAO，最后动 BaseDAOXL每批全量测试绿且用例数不下降；no-floating-promises 零违例
42 表 / 102 索引 DDL 平移 + 类型映射规则表（见 01 架构 §2）：TEXT 时间戳→timestamptz、epoch ms→bigint、JSON 文本→jsonb、0/1→bool、AUTOINCREMENT→IDENTITY（+ setval）L逐表列比对；SCHEMA_VERSION 幂等 exec 纪律照旧
3 张 FTS5 虚表 → pg_search BM25 + jieba；MATCH 27 处改写；顺手修掉 sessions/messages 中文 0 命中M30 条中文双字回归集在执行分区上也命中 > 0
88 个用 :memory: 的测试重做 harness：template 库 + 每例事务回滚（TRUNCATE 兜底）；PRAGMA 62 处整类删除L用例数与迁移前一致；单例可独立跑（不靠执行顺序）
74MB 数据一次性搬迁（COPY），幂等可重跑；启动清扫把 running 孤儿执行标记 interrupted（异步化后新增的必要环节）M逐表行数 + 抽样列值比对通过，不是「跑起来了」
账本三件套（llm_calls_costed 视图、LEDGER_SQL、PRICED_AGG）平移；门禁 G1–G4 与 gold 表全部保持绿M同一数据集迁移前后逐位相等（三态 —/≈/实数不变）
旧 SQLite 只读保留一个版本周期，作为回切读的退路S下线时间点写进 ADR-0024
退出判据：① 全量测试在 PG harness 下绿且用例数与迁移前一致；② 执行链路 p99 不劣化；③ 事件循环阻塞监控为空（异步化后不应再有任何 >50ms 同步 DB 调用——这条同时是"漏 await"的探测器）；④ 账本与 formatter 四道门禁全绿；⑤ 恢复演练成功一次。五条全绿才开 P2。

本阶段明确不做：知识分区任何表、采集器、embedding。地基没干就刷漆是这次最容易犯的错。

P2地图 · 3 周

知识分区落地 + 拓扑骨架建起来

目标：让「这个需求涉及哪个仓库」第一次有可查的依据。地图初期允许不全——缺的节点标 unknown，禁止猜测填充。

交付物量验收
知识分区 schema 六区（topology/contract/experience/decision/eval/ops）建进同一座库 + 与执行分区的 FK 边界 + 迁移器（沿用 SCHEMA_VERSION 幂等纪律）M迁移可重放、可回滚；跨区 FK 可建（这是单引擎直接买到的能力）
采集器 SPI（Finding / URN / evidence / collectorVersion / schemaVersion）+ 三源对账与冲突规则落库M同一边 static+runtime 命中 → confirmed
采集器：maven-deps（mvn dependency:tree -DoutputType=json）· pkg-deps · idl-contract · manual-register UIM≥10 个真实仓库有依赖边与 owner
7 个图算子（递归 CTE）+ BM25(jieba) 检索 + 仓库登记与刷新调度（三级失效：repo×module×file）L三类问题可答且每条边可回溯
SkyWalking adapter 只留接口与 URN 对齐约定，不实现S接口文档 + 冲突规则测试
退出判据：对 ≥10 个真实仓库能答「谁依赖它 / 它暴露哪些接口 / 谁在调」，每条边可回溯到 文件:行 或 pom 坐标；地图刷新一次 < 10min（10 仓）。

本阶段明确不做：Spring endpoint 字节码精抽（P2.5）、多语言 HTTP 边（P2.5+，量 L）、embedding。

第一个真正「跨仓库」的能力在这里出现

退出判据：草稿期跨仓候选在 3 个真实需求上正确且影响面可核对；注入 10 条 100% 可解释；召回抛错时任务仍完成并显式标注「未获知识加持」（G9 故障注入）。
P5决策与反思 · 2 周

判断与生成解耦，归档真的会改行为

交付物量验收
typed decision schema（zod 单入口）+ d_ledger + precedents_for + 因果链MG7：决策可审计率 100%
成本分层 cascade（规则/检索 → 廉价判别 → 低置信才 LLM）M「不碰大模型占比」建立基线（不设假 KPI）。诚实预告：第一层规则来自 d_ledger 历史，冷启动期台账是空的 → 前 4–8 周 cascade 预期命中率为 0，决策成本 = 现状 + 召回开销，比现在更贵。基线只在 d_ledger ≥ 500 行后才开始解读
决策入 llm_calls（新 source_path，沿用三态）→ 角标/看板 chip 直接可见S账本单源纪律不破（ledger gate 绿）
归档反思结构化：与既有经验做印证/反驳/新增判定，五条反馈边全部接通L每条边日触发次数可观测，长期为 0 即报警
归因两层（正则四分类 + LLM 强制引用证据）；定位为「候选根因 + 人工确认」M归因结果必须带证据 id，否则不产出
退出判据：至少 1 次「反思改写了某条经验的置信度」的真实留档；五条反馈边各自日触发 > 0；决策成本出现在刚上线的角标上。
P6评估台与门 · 2 周

让「变好」可证明

交付物量验收
验收口径：organization_action_success 与 information_integrity 两个正交指标（借 OpenViking，对齐 autonomous_grader 而非 grader.py 的同义实现）M指标可跑、可回归
注入对照臂（G12）：随机 10% 的注入位走「关闭」臂，落 injection_arm，出 organization_action_success 差值M差值可算、可回归；占比 < 5% 即告警。这是全套方案里唯一能回答「知识库到底有没有用」的东西
提案关闭纪律（G11）：归档时写 proposal_outcome，算 missed / spurious 差集M漏报率可出数；未关闭的 open 提案使归档报错
主动检索率 = recall_calls / eligible_node_executions 进 actuatorS长期 < 5% 则显式标注「agent 自主检索未落地」，不许含糊
中文召回回归集 + 预算符合率 + 回链完整率 + 提案准确率 四套固定 caseMCI 可跑
do-no-harm 硬门：候选经验/SKILL 变更在既有 task_phase_acceptances case 集上净分不降才晋升L至少 1 次「门拦住退化」的留档
经验健康度看板 + actuator 端点M退化注入实验能被看见
退出判据：故意写坏一条高置信经验 → 看板可见、门能拦；对照差、漏报率、主动检索率三个数都能出数且被诚实记录（哪怕是负的或很难看）；回归集全绿才算体系建成。若对照差 ≈ 0，结论是「本体系当前无收益」，必须公开写进 ADR，不许改口径重测。

此阶段之后才立项：holdout 60/40、负版本号候选、回滚持久门、evidence floor 退役、有界 cap（Ratchet 那套）。理由：单机无 eval 语料时它们是空转。

ADR-0024 全平台单引擎 Postgres（含 SQLite 退场）ParadeDB(PG18) 单容器承载执行分区 + 知识分区，一座库、一个事务；SQLite 退场；不引 Neo4j/Qdrant/ClickHouse/Milvus/AGE。被否决方案必须写全：① 双平面（SQLite 执行面 + PG 知识面 + outbox 投影）——理由是「零迁移」是假收益（166 文件全锁在 packages/server，迁移面封闭），而代价是永久子系统；② 双写；③ CDC；④ 三件套。这是本体系最大的一次自我推翻（上一版明确采用双平面并写了整节一致性设计）。不写下「为什么当时选双平面、后来又为什么推翻」，半年后一定有人再问一遍，或者更糟——有人把它改回去
ADR-0024a 单点风险的接受声明明文承认单引擎是可用性净下降；列出缓解（自动重启 / 备份 + 恢复演练 / 池与超时 / 慢查询可观测）与不做的（HA、pgbouncer、只读副本）及各自的重新评估触发条件「为什么不搞高可用」会被反复问；且这条声明是用户已知情同意的记录，不是技术细节
ADR-0025 图层用算子不用图语言递归 CTE + 固定算子词表；AGE 为后端可替换位；离线图副本为图算法出路本轮讨论的完整理由（含 AGE 实测短板数据）必须留档
ADR-0026 经验契约必挂节点、必带证据快照、默认 quarantine、置信度不信自报这是与今天最大的分歧点，最容易被「先落一条再说」破窗
ADR-0027 人写真源豁免SKILL.md / core-pack / ADR-术语 append-only 三条腿机器不可覆盖；投影只进 _generated/否则一定会有 agent 把人写的技能文件冲掉
ADR-0028 决策层与 Jev 边界只搬方法论（typed verdict + cascade + 台账），不引闭源权重「为什么不接 Jev API」会被反复问
ADR-0029 检索终点是提案可逆、dry-run、必带 impact.path、允许 abstain这条决定了体系是否需要对判断负责
ADR-0030 迁移前置门tsc ratchet + no-floating-promises + 用例数不降，先于任何 DAO 异步化；判据不满足则迁移不得合并没有这条，P1 会在「反正先迁完再说」的压力下被跳过，而 R3 的静默漂移正是这么来的
验收走查脚本（P4 完成后必须能演）：① 新建草稿写「把 X 的报价导出改成异步任务」→ agent 给出候选仓库 repo:B 并显示 endpoint:POST+/quote/export ← calls ← service:A 的路径与证据；② 执行期某 agent 节点自动拿到 B 的测试环境与数据准备方法（带 tested_by 来源）；③ 该任务归档后，一条踩坑经验进 quarantine → 人工确认 → active → 下一次同类任务在动手前被提示。这三步走通，就是体系成立；走不通，前面所有表结构都白写。
P1 还有一条独立走查：把某条经验挂到它的来源 node_execution 与 llm_calls 行上，用一条 SQL join 出「谁提的 · 哪次执行 · 跑了多久 · 花了多少钱」。这在双平面下需要跨引擎拼或干脆做不到——它是单引擎这一决策的可演示成果，也是唯一能让这笔 3–5 周投资被肉眼看见的东西。
