三横切

A · 单一接口面 四类消费者共用切口经评审修正

  • recall(query, scope, budget) / record(candidate) / adjudicate(batch) / evaluate(change)
  • 暴露为：Hono 路由 · 系统 agent 读工具（补当前 0 检索工具）· 引擎注入 · MCP tool 给 clone/skill
  • 切口修正：不给 knowledgeInjectorFactory 加 node/query 入参（类型声明散布 6 处、loop.ts:636 还在 as any 裸转，位参链漂移风险高——sub-workflow 三连 undefined 就是实证）。改为把 recall 回调塞进 InjectorConfig（knowledge-injector.ts:16-18）由 server 工厂闭包注入，engine 类型零改动、只动 2 文件
  • precomputeHook 每次执行仅跑一次、无节点粒度 → 只能做预取，不承担相关性
补齐 swarm / loop / sub-workflow / hook 的注入接线（诊断#4）是本体系「所有节点可引用」的前置条件。

B · 可观测与归因 不承诺全自动目标下调

  • error-tracker 从进程内 1000 条环形数组落库
  • 归因两层：正则四分类（infra/model/input/agent）+ LLM 三分类强制引用证据字段（agent-insight attribution-prompt.ts:12-33）
  • 放弃「全自动 step-level 根因」：真实手工轨迹上 step-level 归因普遍 <25%（DCFA Table 1：Hand-crafted 列 6 模型均值 20.69%、最高单点 24.14%=GPT-5）
  • 定位改为「候选根因 + 人工确认」——这是我们的保守选择，DCFA 本身反而主张全自动
  • actuator 增经验健康度端点（条目数、回链完整率、quarantine 占比、召回命中率）

C · 门禁 沿用仓库文化，但改法2/4 可扫源码

  • 能写成 revival-gate 的（复用 ledger-revival-gate 第三式「单写入口扫描」:68-77）：① INSERT INTO experiences 只许出现在指定 DAO；③ pool.set("__relevant_rule_ids") 只许出现在 recall 模块
  • 扫源码写不出的（内容/语义不变量，硬写就是正则地狱）：② 投影必可反查 id → 改确定性单函数生成器 + 性质测试；④ 决策必 typed → 改唯一入口 + zod parse + 单入口扫描

  • 新增第 0 道门：tsc --noEmit ratchet 基线进 CI（只减不增，基线 690）——否则同类签名 bug 还会再来

05决策层：Jev 能借的与不能借的

Jev 是什么（核查后）不引权重

  • TypeSafe AI 的闭源「System One」决策模型（2026-09-15 发布）：不生成文本，只输出带类型约束+概率的结构化判断。
  • 无 arXiv 论文、无公开权重、无训练细节（官方博客+文档亲自点开确认）。
  • 「零幻觉」的实质是输出被 schema 限死、只能选合法选项——仍可能选错合法项，且缺数学/日期处理。
  • 快 40–200 倍、成本 193.6x/444x 均自报、无对照细节、不可独立复现；独立实测：Laya 32.8ms vs Jev 236–276ms、准确率 0.766 vs 0.727，并明言「200x 缺乏受控比较」。
  • 中文圈的「JEV 工程学」= 在它之上总结的工程分层方法论（非官方术语）。适用边界：封闭集分类/路由/门禁成立；开放生成、复杂/数值推理不成立。
开源替身若真要上：Laya（Apache-2.0，含权重+训练+评测）或 Nokia AnyJev（免训练校准头，把任意开放 LLM 变校准决策模型——最适合套我们现有 providers）。

我们真正落地的 3 件事 与模型无关

  • typed decision schema：verdict 枚举 + confidence + 引用证据条目 id。收益是「决策可审计、可统计、可回放」，与用什么模型无关。
  • 成本分层 cascade：例行判断先过规则/检索廉价层，低置信才升级 LLM。80% 决策不碰大模型——这一条不需要任何新模型就能拿到 Jev 宣称的主要收益方向。
  • 决策入账：写进现有 llm_calls（新增 source_path 枚举），沿用「钱查询时现算、NULL=未定价 → —/≈/实数三态」纪律，可直接被刚上线的角标/看板 chip 看见。
  • 落点：workflow 门禁判定、节点模型路由、失败 triage。
搬不动的：Jev 权重（闭源 API = 新增外部依赖+数据出境）、RLCD 训练法（无论文）、DiffusionGemma 单步去噪直读（重度 GPU 推理栈，与 TS/Hono/SQLite 单机不匹配）。

这一节全部来自一手文献/issue，且刻意避开「跑分选型」——因为跑分本身是最不可信的一环。

可直接搬的验收口径核到实现

  • OpenViking memory_organization：事实带不可变 Fxx 标记，grader 确定性检查放置/保留/重复/删除 → 两个正交指标 organization_action_success（组织动作对不对）与 information_integrity（信息有没有丢）。出处 README.md:32-35 + autonomous_grader.py:162/214-215；注意 grader.py 里是另一对同义不同名实现（organization_success / content_organization_success）——搬时对齐前者
  • Ratchet 三条卫生规则（AWS+HSBC，arXiv 2605.22148；实现 amazon-science/Self-Evolving-Agents-Ratchet，Apache-2.0，含 skillevo/ 与 39 个测试）：① 训练/留出 60/40 严格不相交，留出任务永不进合成链；② 回滚持久门「跌 >0.10 且连续 5 轮」（300 决策仅触发 2 次 → 增益非门制造）；③ evidence floor 退役（n(s)≥N_min=100 且 ĉ(s)≤−τ=0.10）
  • LongMemEval 的 5 能力维度（抽取/跨会话/时间推理/知识更新/拒答）适合当召回验收轴——⚠ 原论文未亲自点开，标 UNVERIFIED，引用时须补
Ratchet v3 已改名《How Reliable Must an LLM Judge Be to Retire a Skill?》；其命题是 "a floor, not a convergence rate"（保证不下界发散，不保证提升）；A7 段自陈 cap 在该规模 non-binding，参考实现仍保留 0.85 余弦显式去重 → 「去重不必要」只能写成「非承重」。

必须写进设计的陷阱我们原本会踩

  • LLM 自产 skill 无收益甚至负收益：SkillsBench v1「curated +16.2pp、自产平均 no benefit」；v4 主聚合 33.9%→50.5%(+16.6pp，87 任务/18 配置)。−8.1~−11.5pp 只出自 Table 6 的 3 个 dedicated-harness 配置，作者明示「retained as a diagnostic，不计入主聚合」，且给出 4 种非知识性成因（包未被读、creator 抢占、confident error、leakage）→ 不可写成普适负收益，但结论方向成立：瓶颈是图书管理员，不是作者。
  • 不能用日志回放验证改动：The Replay Gap（CMU，arXiv 2608.08239）回放状态仅 ~3% 有效、回放式评估器对每个关键成败都判错。⚠ 该文范围是 per-step 模型替换/路由评估（6 配对 ~900 rollouts SWE-bench）——我们采纳「分叉 + 同模型对照臂」是方法迁移，不是它的证据
  • 不要拿 LoCoMo 分数选型：getzep/zep-papers#5（已 closed 因 inactive）中 25.56pp 是 Mem0 CTO 单方口径，Zep 官方反驳并自改 75.14%（≈9pp）；mem0ai/mem0#2800（closed）是「开源 SDK 复现不出平台版分数，因平台版加了 contextual-add/自定义指令」→ 与「口径摆动 25pp」不是一回事。各家基准均为自报
  • 全自动 step-level 归因：真实手工轨迹普遍 <25%（见横切 B）
  • 写时编译知识库进企业的三死因：ACL 冲突致编译成本量级错误、幻觉污染复利、矛盾知识无 Owner（腾讯云《Agent Wiki 火了五个月》✅，论证型无量化）→ 对应我们的「quarantine + 人写真源豁免 + owner 字段」
我建议的自研验收口径（不是跑分，是门禁）： ① 回链完整率 100%（每条经验都有可解析的证据快照，CHECK 约束）； ② 中文双字召回：固定 30 条双字/三字查询用例，命中率 > 0（今天恒为 0）； ③ 注入预算符合率：装配结果永不被硬截（超档回退），且 quarantine 条目注入数 = 0； ④ information_integrity：合并/裁决前后 Fxx 事实集合比对（丢一条即红）； ⑤ 净分不降：候选经验/SKILL 变更必须在既有验收 case 集上不退； ⑥ 决策可审计率：100% 决策带 typed verdict + 证据 id。
