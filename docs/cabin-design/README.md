# 工作舱原型 · 版本索引

> 每个文件都是可独立打开的自包含 HTML（直接 `open`）。立绘在 `crew/`。
> 设计稿：`design/09-cockpit-v2.md`（驾座演进）、`design/10-workbench-and-cabin.md`（两种模式）。

## 两种模式（当前采用）

- `index-v2.html` — **工作台 · 默认版**：任务 + 会话，两栏，无浮窗；从这里进入工作舱。
- `cockpit-v7.html` — **工作舱 · 沉浸版**：一个 CWD，任务 / 会话两个原语；运行、变更、Trace 是任务里的镜头；可切回工作台。
- 两个文件共用同一份 mock 数据、同一套状态与动作词汇；`#task=…&lens=…` / `#session=…` / `#view=trace` 保当前视图。
- `cockpit-v6.html` 保留作对照：它把项目 × 运行 × 任务 × 会话 + 5 个作业面都展开了，层偏多；v7 是收口版。

## classic 设计线（2026-11-13 起）

- `classic-v1.html` — 以 `index.html` 为底的第一版收敛稿：固定坞位、去「更多」、去输入条目录、身份=汐音舰长、工作舱→作战舱。
- `classic-v2.html` — **指挥甲板（探索稿，未采用）**：并行作业三栏 + 右栏现场，验证了「点作业不切走指挥台」的交互，
  但信息密度仍偏高。方向转为 `classic/`：舱外 classic、舱内沉浸，两边切换。
- `classic-v3.html` — **安静指挥**：主模式完全沿用 v1（侧栏 + chat + 固定作业坞），只补三件小事：
  ① 编队面板（右侧，可读列表：类型字形 + 名字 + 状态 + 进度，点击看详情）；
  ② 作业详情（点 → 面）：概览（汐音 ↔ 作业的派发/回报/需注意/人输入时间线）、对接（你 → 汐音 → 执行者 三方同屏，agent 的话只作回执）、运行（省略态执行摘要：状态·工作流·用时·节点进度；「打开运行 →」开作业坞运行窗，DAG/日志/YAML 都在）、变更（任务 / phase 两级，目录树 + 点文件看 diff）、验收；都在这一扇窗里看完，不设「打开独立任务」这类跳转；
     验收走 chat：说「验收 X」，汐音把对应任务的验收窗摆出来，你看、你拍板（不会自动放行）；
  派发时一条「飞入编队」动效，验收/打回有收束动画；不铺满屏消息。
  **概览收成三个入口**：任务（四列看板 + 迭代筛选，吸收原任务看板/迭代窗）、工程（仓库行展开工作树，吸收原仓库/工作树窗）、记录（归档 / 通信 Trace 两标签，吸收原归档/Trace 窗）；调试只在坞上，不在概览重复放。
  原 7 个模块窗收成 3 个，弹窗里的设计说明长文去掉，只留数据与一句操作提示。
  v1 的「统一作业」窗口撤掉；运行 / 变更 / 验收从作业坞撤掉 —— 它们都在作业详情里，坞里只留 文件/活动/调试/消耗 + 概览。
  顶栏补消耗统计；宽屏下 chat 左对齐，右侧留给编队面板与作业坞。
- `classic-v4.html` — **助理菜单重设计（讨论稿，2026-11-13；第二稿）**：v3 之上只动「助理菜单」，总高比 v3 还矮 12px、无内滚动——
  ① 色调条压成一行：色调 + 六套小色块直接点 +「随机」（图标钮；只换色调，整套悬浮/光效风格的随机仍在舱面调校里）；
  ② 统计行三个数字变成可点入口：运行 / 需要你 / 队列 各自打开对应窗口；
  ③ 菜单保持 v3 的顺序与条目；「互动一下」不再单列（点立绘就是互动），立绘画廊去掉误导性的「9」角标、数量放进副标题。
  ④ 新增**在场**（定时 + 随机时间）：汐音按随机间隔主动搭话（原型「演示」档 25–50s；正式版安静 12–24 / 标准 6–16 / 活跃 3–8 分钟）。
     到点还要过闸门：页面在前台、你 60s（原型 12s）没动键鼠、没在回复、助理菜单没开着、22:00–08:00 免打扰。
     话术事实优先（需要你 > 回流队列 > 运行中），每三轮夹一条闲聊，避免复读；事实类带「看需要你 →／开队列 →／看运行 →」，
     另有「静 30 分」。对话只出现在立绘旁，**不写进 chat**（不污染 transcript、不花 token）；离开 >10 分钟回来补报一次回流。
     开关 / 频率 / 下次时间 /「现在说一句」都在舱面调校；菜单里舱面调校那行显示在场开 / 关。
  待讨论：主动话术用模板（零 token）还是让模型现说；画廊是否需要真正的「新」标记。

## 双模式 · `pair/`（两个独立页面，2026-11-13 起）

- `pair/classic.html` — **舱外 classic**：左栏作战舱 / 任务 / 会话 + chat；作战舱行「进舱 →」。
- `pair/cabin.html` — **舱内沉浸**：汐音 + 编队 + 一条指令条 + 顶部三个数字；「◀ 出舱」。
- 两页各自可单独打开，互相跳转；会话选择与编队状态存 `sessionStorage`，来回切换不丢。
- 这是 `classic/` 单文件演示的拆分版（两页独立、互链），视觉与交互一致。

## 双模式 · `classic/`（单文件演示）

`classic/index.html` 一套演示「出舱 / 进舱」：

- **舱外 classic**：左栏作战舱/任务/会话 + chat，保持现网风格；点作战舱行进舱。
- **舱内沉浸**：默认只有汐音、编队（6 个 tile）、一条指令条、顶部三个数字。没有常驻面板和说明文字。
  点 tile 才滑出现场；点 ✉ 才拉开通讯层；顶部「出舱」或 Esc 回到 classic，会话保留。
- 舱内是 cockpit-v5 的收敛版：去掉常驻面板与文字，只留角色 + 编队 + 指令条。详见 `classic/README.md`。

## 版本差别

- **v1**：没有独立对话列。派发靠底部指令条，汐音的反馈是立绘旁的气泡 + 右上角简报卡。
  信息最干净、驾座感最强；代价是看不到历史对话。
- **v2**：对话成为主列；打开证据时右栏整体让位，汐音暂时离场。
- **v3**：右栏更大（安静时是 660px 的驾座舞台，大立绘 + 任务时钟）；
  打开证据时立绘缩成 220×330 的「随行舱」停在左下角，证据抽屉在右侧展开。汐音始终在屏幕上。
- **v4**：以 v2 为底，补上 v1 的「到达感」——任务到达时右上滑入简报卡、汐音头顶弹出漫画对话框
  （打字机逐字、带指向她的尾巴）、情绪切换、注意力栏脉冲；动作卡仍是 v2 的形式
  （点按钮 = 往对话里发一句话，卡片随即置灰）。
  关键修正：**三分区 + 弹窗**——汐音在左（头顶漫画对话框）、对话在中、任务列表在右；
  证据面板从右侧滑出、覆盖任务列表与对话右缘，汐音永远是原尺寸的大立绘，
  不会被挤成横条或侧栏，对话始终留在中间。弹窗底部带本场景的主动作（通过验收 / 拍板 / rebase 重跑），
  点它与点对话卡片走同一套反馈。
- **v5**：回到 v1 的构图，把 chat 从「第四列」改成「一个模式」——
  **通讯层**和场景面板共用同一块内容区（立绘右侧），互相替代，布局永不回流；
  指令条上方常驻一行**回执 ticker**，点开即展开通讯层；通讯层可**钉住**，钉住后关掉面板会自动回来。
  立绘在所有状态下都是原尺寸。
  **回复即操作**：卡片只展示信息 + 一个「看证据」文字链，决策靠你在指令条回一句
  （通过 / 退回 / 600 / rebase）；`interpret()` 听懂后落状态并回执；面板按钮降级成「兜底」，
  用同一套词并给主操作加一圈高亮。舱里只和汐音对话（问问汐音），不和分身聊。
- **v6**：v5 是基线，把原来 P1–P5 的作业面一次性补回舱里，回答「多项目、多任务、多工作流、多会话」：
  **指挥台**是唯一总账——3 个项目、4 条工作流、3 个任务、4 个分身同屏，运行中 / 等你 / 阻塞 / 排队一眼分清；
  点对象进入**运行**（节点图 + 实时流 + 节点产物 + 中止/重跑）、**任务交付**（阶段时间线、交付物、PR/分支/提交、
  AC）、**变更**（改动文件 + diff + 校验）、**分身会话**（多会话流水、工具调用、token、接管/暂停）。
  **Trace** 是这一版的审计面：座舱拓扑（汐音 → 对话/任务/归档 Agent → 工作流）+ 交互流
  （人输入/派发/回报/需注意/工具）+ 按主体/模型的消耗（chat 与 subagent 分列防双算）；点节点或说名字即可过滤。
  导航走对象关系（任务 → 运行 → 变更 → 会话 ⇄ Trace），不走 tab；仍然一次只开一块内容区，立绘在任何界面都不缩放。
  面板按钮仍是兜底；你说「重跑 / 中止 / 发起交付 / 接管 / 看 trace / 指挥台」都能落状态。
- **index-v2（默认工作台）**：原 `index.html` 的 17 模块 / 浮窗全部收掉，只留**任务 + 会话**。
  左栏是等你 / 任务（绘画 / 开发筛选）/ 会话；主区是任务页与明确的镜头栏（开发：概览/运行/变更/Trace；
  直做：概览/会话/变更/Trace；绘画：概览/版本/素材/交付），会话是独立 transcript。
  没有浮窗、没有 dock；底部指令条始终是汐音；「进入工作舱 →」保留任务/镜头切过去。
- **v7（沉浸工作舱）**：v6 的层收口。舱内不再有项目维度（一个 CWD 一个舱）；顶层只有任务 / 会话 / 等你；
  运行、变更、Trace 变成任务的镜头，注意力卡直接打开对应镜头；任务舱只有三块。
  保留 v6 的立绘原尺寸、通讯层、回复即操作、兜底按钮；新增 4 套皮肤、与工作台的双向切换。
  v7 不再有 v6 的「项目条 / 运行列表 / 四个并列下钻」——它们都被收进任务与任务镜头。

## 共同的后端假设

`GET /api/cabins/:id/view` 的 `attention[]` 已带 `stage / task_id / repo / wt / deep_link`，
场景可直接由 `stage` 映射；卡片按钮发的是一句普通对话，不需要新端点。

一个舱对应一个 CWD；多项目 = 多个 cabin，舱内不再有项目筛选。任务分绘画 / 开发（工作流 / 直做），
会话是任务的执行现场；运行、变更、Trace 都是任务的镜头，不是顶层对象。

v6 / v7 的作业面按现有读模型拼：`view.workflows`（运行 + 节点 + 状态）、`view.tasks`（phase / 交付物 / AC）、
`GET /api/agent/sessions/running`（分身会话 + token）、`git status/diff`（变更文件）。
Trace 直接复用 P1–P5 的审计读模型：`cabin_job_events`（派发/回报/需注意 + actor + summary）、
`llm_calls_costed`（成本查询时派生）、`subagent_runs`（子代理 token 单列）；chat 行以 `execution_id IS NULL` 区分，避免双算。
原型只依赖这些读模型，不引入新的写语义——「重跑 / 中止 / 发起交付 / 接管」仍回落到一句对话，
由汐音落到既有执行器上。
