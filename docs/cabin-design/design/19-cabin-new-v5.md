## 0. 用户原话（2026-11-15，逐字）

> 首先的话，我觉得这个地方操作有问题吧。我点到创建的时候，这里要点过 3 个界面才到那个开始初始化这里不行啊，这里只要 1 当前首页界面选择完对应的就 OK，就可以直接进入初始化了。不要这样子在后面再跳两个界面是吧，这个设计一下这个新建这个作战舱这里这样太繁琐了。然后的话做建仓的名字的话，这里如果用户不填的话，它其实是要 Agent 它在进行初始化的时候，它会默认给他输入一个那个作战仓的名字的，因为我们上来必填一个对这个作战舱的描述，并且他想要干什么活的话，是吧，可以优化一下。在原来的原型的基础上稍微再修改一下，给个 v5，我再确认一下这个原型还有操作逻辑吧。

**读法**：

1. 现在点「开始创建」要过 **3 个界面**（输入页 → 她的提案页 → 已创建页）才真正开始初始化 —— 不行。**只要 1 屏**：这一屏选完，点下去就直接建、直接进初始化。
2. **舱名不是必填**：不填也没关系，初始化的时候由 Agent 按需求默认取一个 —— 因为需求（描述 + 要干什么活）本来就是必填的，名字有依据。
3. 在 v4 原型上**小改**，出 v5，先确认原型和操作逻辑，再改代码。

## 1. v4 → v5：只改两件事

| | v4（已实现） | v5 |
|---|---|---|
| 点「开始创建」之后 | 她的提案页（舱名 + 初始化意见 + 回去改需求）→ 「就按这个开」→ 落舱 → 已创建页 → 「进入作战舱」 | **提交即建**，直接进舱，门禁在舱里跑 |
| 中间界面数 | 3（输入 → 提案 → 完成） | **1**（输入就是全部） |
| 舱名 | 不能填，她取、你点头 | **可选输入**：填了用你的；不填由初始化取名，不再问你 |
| 名字的确认 | 必须你点头 | 没有确认这一步 |
| 回退 | 提案页可以「回去改需求」 | 回退只在提交前（`×` / 走开）；提交后要撤就是删舱 |

其余全部保留，不动：大 composer、需求是唯一必填、汐音大立绘 + 登场、目录默认新建工作空间、系统式选目录窗、**一个目录 = 一个舱**、项目跨 org 绑定 + 搜索 + 回显、`⏎` 提交。

## 2. 这一屏

```
                      ┌───────────────┐
                      │    汐音        │     286 × 330，登场一次
                      └───────────────┘
                        开个新舱。说说它要做什么。
                名字可以不填 —— 初始化时我按你说的取；目录不选就新建

          ┌──────────────────────────────────────────────────────┐
          │  描述这个作战舱要做什么…说得越清楚，我取的名字越准。      │
          │  比如：做一个电商后台，长期维护订单、库存和结算对账      │
          │  ┌目录┐┌绑定项目 2┐┌ 舱名（可选） ┐                    │
          │                              ⏎ 开始创建  [开始创建]  │
          └──────────────────────────────────────────────────────┘
          一个目录 = 一个舱 · 舱名不填就由她在初始化时取 · 提交即建
```

- **舱名**是第三颗控件，虚线边框 + 占位「舱名（可选）」：一眼看出可以不填，点进去就能改；填了变实心。它和目录/项目同一行，不抢需求的注意力。不额外写解释文案（用户 2026-11-15 明确要求）。
- 需求为空 → 「开始创建」不可用；`⏎` 直接提交（`⇧⏎` 换行），`⌘⏎` 等价。
- 目录选中已有舱 → 同上稿：琥珀提示 + 主按钮变「打开「X舱」」，点了只进舱、零写操作。
- 左栏草稿行实时跟着你填的舱名走（不填就还是「未命名舱 · 草稿中」）。

## 3. 提交之后（没有第二屏）

```
[开始创建]
  │ 按钮就地变「正在落舱…」，舞台那一句改成「现在就在建」
  ├─ POST /api/cabins   { name?, path?, requirements, projects[] }  → { cabin, created }
  │    name 空 → 服务端存「未命名舱」，名字留给初始化取
  ├─ 左栏：草稿行当场变正式舱行（状态「初始化中」，琥珀点）
  ├─ 右页：直接进舱（tab 换成舱名 · 门禁在舱里跑）
  ├─ POST /api/cabins/:id/init
  │    ├─ 第 0 步：取名（见 §4）
  │    ├─ gate 1 目录可写 · 2 git 可用 · 3 克隆仓库 · 4 主线分支
  │    ├─ gate 5 舱骨架 .cabin/ · 6 需求落盘 .cabin/requirements.md
  │    └─ gate 7 首批任务建议（真实 agent 回合：读 requirements，给出首批任务建议，不派发）
  └─ 门禁卡全绿 → 舱行变「就绪」→ 她的第一段话就是首批任务建议
```

- 门禁卡就是现在实现里的 `CabinInitGateCard`（7 项、等宽、逐项 ✓ / … / ○），不是新东西。
- **create 失败**：留在这一屏，原文不丢，toast 报错，按钮回「开始创建」；不建半截的舱行。
- **init 失败**：舱照样进得去，门禁卡红色 + 「重试门禁（跳过已完成项）」—— 已有能力，不动。
- 提交前取消（`×` / 草稿行 `×`）仍然零请求；走开（点别的舱/任务）草稿留着。

## 4. 名字：三条规则

| 情况 | 结果 |
|---|---|
| 你填了 | 就用你的（trim，≤16 字）。初始化不再改名，她第一段话直接进首批任务建议 |
| 你没填 | 初始化**第 0 步**取一个名：关键词表（电商/订单/对账/健康/知识…）→ 需求去掉动词前缀后前 2–4 字 + 「舱」→ 兜底「新舱」 |
| 想改 | 以后在舱内设置里改；这一稿不做入口（改了也只是称呼，目录才是身份） |

**为什么取名放在初始化里、而不是提交前**：

- 需求必填且已经是「这个舱干什么活」的完整描述 —— 名字的可依据信息全在这一段里，交给初始化最自然；
- 你什么都不用点；名字有把握时才取（关键词命中），没命中就先给个可读的短名；
- 取名在 gate 1 之前完成，所以 gate 7 的提示语里已经是真名（「作战舱「电商舱」已就绪…」）。
  实现上就是一个纯函数 `nameForRequirements(req)`，**要接模型只换函数体**，门禁与接口都不变。

**原型为了让你看清这一拍**，把「未命名舱 → 电商舱」拖到门禁跑完之后，并在对话里给一句
「名字我想好了：这个舱就叫 **电商舱** —— 你说的是电商后台，取这个最省口舌。」
真实实现里这个中间态只有毫秒级；这句话保留在她门禁 7 的回合里（说一次，不重复）。

## 6. 验收（逐条可点）

1. 一屏只有：立绘、一句、大输入框、三颗控件、主按钮；**没有舱名字段也能提交**。
2. 需求为空 → 按钮 disabled；填了 → 亮；`⏎` 直接提交。
3. 点「开始创建」→ **没有第二屏**，直接在舱里看门禁逐项跑完（1→7）。
4. 不填舱名 → 舱行先「未命名舱 · 初始化中」→ 取名后行 / 舱头一起变；对话里她说一句为什么叫这个。
5. 填舱名 → 用它，初始化不再改名，第一段话直接是首批任务建议。
6. 选已有舱的目录 → 琥珀提示 + 「打开「X舱」」，点了只进舱，`POST /api/cabins` 计数 0。
7. 提交前 `×` / 走开 → 零请求，草稿按原语义保留或丢弃。
8. create 失败 → 留在这一屏、原文还在、按钮可重试。
9. init 失败 → 舱进得去，门禁卡红 + 可重试，名字照样有。
10. 560 窄屏、reduced-motion：无动画、逐字直接出全文，布局不出界。
