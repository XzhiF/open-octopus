## 1. 这一屏只有三样东西

```
                      ┌───────────────┐
                      │               │     汐音：立绘 286 × 330，融进背景，
                      │    汐音        │     登场一次（升起 + 光圈 + 星屑 + 逐字）
                      │               │
                      └───────────────┘
                        开个新舱。说说它要做什么。
                   名字和项目我来安排 —— 你只要说清楚这个舱是干什么的。

          ┌──────────────────────────────────────────────────────┐
          │  描述这个作战舱要做什么…                               │
          │  比如：做一个电商后台，长期维护订单、库存和结算对账        │
          │  ┌目录┐ ┌绑定项目 3┐              ⏎ 交给汐音  [开始创建]│
          └──────────────────────────────────────────────────────┘
         一个目录 = 一个舱 · 名字由她从你的需求里取 · 你点头才真正建
```

**没有**舱名字段、没有仓库表单、没有进度条、没有小卡片。

## 2. 大输入框 = 唯一的输入

- 跟新建任务同一个量级：`width: min(760px, 100%)`，居中，`border-radius 14`，聚焦时紫色描边 + 3px 光晕。
- 多行 textarea，placeholder 直接给出两个例子（电商后台 / 健康管理），把"该说多细"示范掉。
- **必须说出需求**：textarea 为空时「开始创建」是 disabled 的 —— 这是这一屏唯一的必填项。
- 输入时她换表情（听你说），提交后换"想事情"的表情（托腮 + 问号）。
- `⏎` 交给汐音（普通回车不换行，`⇧⏎` 换行），`⌘⏎` 等价于点「开始创建」。

## 3. 输入框里的两颗控件

### 3.1 目录：默认新建工作空间，点开才是系统式选目录

chip 默认显示 **「新建工作空间」**（不额外解释 —— 新建的舱本来就都有目录，这是常识值）。
点开只有三条：

1. **新建工作空间**（默认档，带「第一次创建时建」）——
   `~/.octopus/workspaces/cabin-<MMDD>-<HHmmss>-<rand6>`，与任务的目录同族
   （dev 库里任务真实路径就是 `~/.octopus/workspaces/task-<slug>-<MMDD>-<HHmmss>-<rand>`）。
2. **已经有的舱** —— 列出已有舱及其目录，用来"顺路看一眼/直接进"。
3. **选择目录…** —— 打开**系统式目录选择窗**（跟新建任务的 cwd 选择同构）：

```
┌ 选择目录 ────────────────────────────── ✕ ┐
│ ↑  ~/Projects/ai/XzhiF                    │
│ (Home) (Projects) (Documents)             │
│ ┌───────────────────────────────────────┐ │
│ │ 📁 open-octopus          已是「八爪舱」│ │
│ │ 📁 ledger                已是「账本舱」│ │
│ │ 📁 aurora                      进入 › │ │
│ └───────────────────────────────────────┘ │
│ 这个目录已经是「账本舱」了 —— 不能在这里再建一个 │
│                      [取消] [打开「账本舱」] │
└───────────────────────────────────────────┘
```

- 上级 / 当前路径 / 根（Home · Projects · Documents）/ 子目录 / 「选择当前目录」；
- 已经在舱里的目录打标签，并**把主按钮换成「打开「X舱」」**；
- 选了普通目录 → chip 显示目录名（`ledger`），tooltip 给全路径；**自动回显项目**（见下）。

### 3.1b 一个目录只能有一个舱（硬规则）

- 目录一旦属于某个舱，**不允许**再开第二个舱；
- 选中这种目录时，输入框上方立刻出现琥珀色提示：
  「这个目录已经是「账本舱」了 —— 一个目录只能有一个舱，不能在这里再建一个。」；
- 主按钮同一刻变成 **「打开「账本舱」」**；点它进已有舱，不写任何东西；
- 在目录选择窗里遇到这种目录，主按钮也是「打开「账本舱」」，而不是"选它然后报错"。

> 之前"没选目录就不让提交"的拦截已经去掉 —— 空着就是「新建工作空间」，这是默认路径。

### 3.2 绑定项目（关联关系，跨 org，带搜索）

项目一多，纯列表就不好用了，所以弹层自带四件东西：

| 部件 | 作用 |
|---|---|
| **搜索框**（打开即聚焦） | 按项目名或 org 过滤，命中部分高亮（`<mark>`）；无结果给「没有匹配「zzz」的项目」 |
| **已选条** | 选中的项目变成可点掉的 chip（`ledger XzhiF ×`），项目多了也能一眼看清选了哪些 |
| **分组计数** | `XzhiF 7 / acme 4 / lab 3` —— 搜索时只留命中的组，计数跟着变 |
| **列表滚动** | `max-height 248px` 自己滚，不把弹层撑出屏幕 |

- 点击弹出按 **org 分组**的列表，勾选即可，**可以同时勾多个 org**；
- 目录原来就有项目 → 直接回显并标一行「已从这个工作空间回显 3 个项目 —— 可以增减，也能跨 org 再加」；
- chip 上给摘要：`web-app +2`；
- 语义写死在弹层底部："项目是关联关系，不搬代码"。

> 用户已说明：**工作空间（workspace）本身还要再设计**。所以这一版只表达"目录 ↔ 项目是多对多关联、可跨 org"，不预设 workspace 的数据模型。见 §7 遗留。

## 4. 不填名字：她取名，你点头

```
你写完需求 → 点「开始创建」（其实是"交给她"）
   ↓
她给提案（同一屏，不跳页）：
   · 舱名：`电商舱`   ← 可改；旁边一句为什么（"你说的是电商后台 —— 名字直接取这个"）
   · 目录：自动建 ~/.octopus/workspaces/cabin-1115-162104-f01335（或你选的目录）
            项目：XzhiF/web-app · XzhiF/engine · acme/billing
   · 初始化：落 .cabin/ 骨架 · 需求写进 requirements.md · 起主会话后我提 M1
   ↓ 「就按这个开」 / 「回去改需求」
才真正 createCabin → init → 进舱
```

- 名字取值规则（原型是关键词表，真实实现交给模型）：`电商 / 订单 / 库存 → 电商舱`、`健康 → 健康舱`、`对账 → 账本舱`…；没有命中就取需求里前 2–4 个字 + 「舱」。
- 左栏草稿行与 tab 名**实时跟着名字变**：`未命名舱` → `电商舱`（待确认）→ 建好后变正式舱行（就绪）。
- 改名字只改称呼，**目录才是身份** —— 这句写在提案下方，避免用户以为改名会换舱。
- 「回去改需求」把面板撤掉、textarea 恢复（内容还在），不丢任何东西。

## 5. 汐音的登场（"意外效果"，不是一小片）

| 要求 | 做法 |
|---|---|
| 不能小气 | 立绘 286 × 330（窄屏 196），占屏幕中上部，不是角落徽章 |
| 她得"在那儿" | 黑底用 `mix-blend-mode: screen` 融掉，配椭圆遮罩 + 背后柔光 —— 没有方框边 |
| 有登场 | 进页：上浮 18px + 淡入（750ms）· 光圈扩散一次（1.35s）· 7 颗 ✦ 星屑（随机方向）· 台词逐字打出 |
| 有反应 | 聚焦输入框 → 换"听你说"的表情；提交 → 换"想事情"（托腮 + 问号）+ 6 颗星屑；建好 → 换"握拳" + 10 颗 + 轻跳一下 |
| 有分寸 | `prefers-reduced-motion` 下全部关掉（不动、不闪、台词直接出全文） |

## 7. 验收

1. 打开即见：大立绘 + 一句 + 居中大输入框 + 两颗控件；**没有舱名字段**。
2. 需求为空 → 「开始创建」disabled；填了 → 亮起。
3. 有需求但不选目录 → 直接提交：提案里写「新建 ~/.octopus/workspaces/cabin-…」，路径与任务目录同族。
3b. 点 chip → 目录层：默认档「新建工作空间」/「已经有的舱」/「选择目录…」；点后者开系统式选择窗（上级 / 路径 / 根 / 列表 / 选择当前目录）。
3c. 选中一个已有舱的目录 → 输入框上方出现"一个目录只能有一个舱"的提示，主按钮变「打开「X舱」」；点了只进舱、零请求。
4. 选已有目录（如 `open-octopus`）→ 项目自动回显 3 个，可增减；勾另一个 org 的项目 → chip 变 `web-app +3`。
4b. 项目面板里搜 `led` → 只剩 `ledger`（命中高亮）；搜 `acme` → 只剩 acme 的 4 个；搜 `zzz` → 空态文案。已选条可单独移除。
5. 点「新建工作空间」输入 `atlas` → chip 变「新建 atlas」，tooltip `~/Projects/XzhiF/atlas`。
6. 提交 → 她给名字（电商 → 电商舱）+ 初始化三条，名字可改且左栏跟随。
7. 「就按这个开」→ `POST /api/cabins` 1 次 → 左栏草稿行变正式舱行 → 进舱第一句是她问"这个舱长期拿它做什么"。
8. 「回去改需求」→ 面板消失、原文还在、零请求。
9. 取消（tab × / 草稿行 ×）→ 空态，零请求，计数不变。
10. reduced-motion：无动画，文字直接显示。

## 8. 遗留

- **workspace ↔ 项目 的数据模型**（用户明说"工作空间到时候要稍微设计一下"）：目录是 workspace 吗？项目挂在 workspace 上还是挂在 org 上？回显的依据是什么？本稿只表达"关联 + 跨 org"，不定义表。
- **自动工作空间的命名**：任务用 `task-<可读 slug>-<时间>-<rand>`，舱这里是 `cabin-<时间>-<rand>`（中文名没法做 slug）。
  如果希望可读（`cabin-dianshang-…`），要么加拼音表，要么让模型顺手给一个 ASCII slug。
- 项目搜索只在前端过滤已拉到的清单；仓库多了以后要不要服务端搜？（`fetchManifestRepos` 现在一次给全量 ≤ 几百个，够用。）
- 窄屏（≤640）左栏收起了，没有「＋ 新建」入口 —— 真实实现走抽屉，原型先没做。
- 回显来源：真实实现应来自 `GET /api/cabins`（该目录注册的舱）+ workspace 的项目关联；原型是硬编码表。
- 名字由模型给时要不要"给三个候选"？（本稿只给一个 + 可改，避免多一次选择。）
- 需求写了很长时，提案里那一段要收几行（现在 66px，超出裁掉，没有展开）。
- 没选目录时她主动开目录弹层，会不会显得催人？可以改成只抖动一下 chip。
