# 14 · 开舱台：新建作战舱 v1（原型待实现）

> 原型：`docs/cabin-design/cabin-new-v1.html`（自包含，直接打开）
> 状态：**设计稿**，尚未改代码。现有实现是 `CabinNewForm`（名称 / 目录 / org+仓库 / 需求备注 的单页表单）。

---

## 0. 用户原话（2026-11-15，逐字）

> 现在给我新建一个原型，是关于新建作战舱的。现在这种弹窗的，要一步一步下一步的，我并不喜欢。我想是像参考是新建任务的那一种，直接打开的话，当我们说话了，保存了，或者说点击开始创建了之后，才进行我的工作上的实际的创建给我重新设计个原始 HTL 吧，就是这个创建新创建的这个新建工作仓，呃，新建那个作业仓的。然后呢，现在作业仓的话，有我们的一个吸音的一个形象在里面，来区分跟其他不同的任务或者绘画的新建方式

**读法**（只归一错字，不改语义）：

- 「吸音」= **汐音**（立绘角色）。
- 「绘画」= **会话**。
- 「作业仓 / 工作仓」= **作战舱**（`/cabin/:id`）。
- 「原始 HTL」= 一份可以直接打开的**原始 HTML 原型**。

**一句话**：开舱不要向导。打开就是一屏，你说话她就写舱面；直到你说「开始创建」/点按钮，才真的动盘；这一屏有汐音在，一眼就跟"新建任务 / 新建会话"区分开。

---

## 1. 她要反对的到底是什么

| 现在 | 她的判断 |
|---|---|
| 新建走**弹窗** | 不喜欢：舱是长期的东西，不该借宿在一个临时窗口里 |
| **一步一步 / 下一步** | 不喜欢：字段彼此没有先后，没必要排队 |
| 表单先于内容 | 不喜欢：她想的不是"填表"，是"跟汐音讲清楚要开一个什么舱" |

而她认可的参照物是**新建任务**那条路：直接打开、说话、由 agent 把你的话落成结构；**真正动手在最后一步的确认**。

**结论**：把「开舱」做成一张常驻的**开舱台**（跟对话同级的一屏），而不是一次事务性的弹窗。

---

## 2. 三条设计原则

1. **一屏即全部，没有下一步。**
   所有字段同时在场：舱名 / 目录 / 注册表仓库 / 需求要点。缺哪个，由汐音在对话里当场点哪个，不做分步。
2. **说话即填写。**
   对话是主要输入：你说「给 ledger 建个长期舱，做结算对账，目录 ~/Projects/.../ledger，仓库用 ledger 和 engine」，
   她把这句话拆成字段写进舱面；每个被她填上的字段闪一下并挂 `✦ 来自对话`。
   舱面上的字段也可以直接改（她写的，你能改）—— 两条路都通。
3. **只有一个闸门。**
   点「开始创建」（或 `⌘⏎`）之前：**不建目录、不建库、不接仓库**，退出即丢弃（可选存本地草稿）。
   点了之后才按 `createCabin → init` 真实执行，进度在同一屏用三步呈现，可随时「停下」。

---

## 3. 为什么这一屏要有汐音（跟任务/会话的区别）

用户要的是"一眼看出这是开舱，不是开任务"：

| 新建 | 有没有舱灵 | 形态 |
|---|---|---|
| 新建任务 | 无 | task-author 会话里聊 |
| 新建会话 | 无 | 空白会话 |
| **新建作战舱** | **有：汐音 · 开舱向导** | 立绘 + 台词 + 她记得（上次目录 / 常用仓库 / 已存在的舱）+ 「舱 ≠ 任务/会话」三行对照 |

落地要点：

- 左栏常驻立绘（286px），表情跟着状态走：待命 / 思考（听你说） / 建舱中（打字） / 提醒（缺字段） / 完成 / 俏皮；
- 她说的话是一条**引导语**（不是聊天记录），随状态替换；右边才是完整对话；
- 「她记得」不是装饰：一键填上次目录、一键加常用仓库——这些正是"她有记忆、任务没有"的证据；
- 底部三行对照：任务=做完就结束 / 会话=聊完沉底 / **舱=一个目录 · 长期活着 · 有汐音**。

## 4. 版面（1440 × 900）

```
┌ 顶栏 ─────────────────────────────────────────────────────────────┐
│ ← 返回对话   ● 新建作战舱  [草稿·尚未创建]  一屏就是全部…   [演示] │
├──────────────┬───────────────────────────────────┬────────────────┤
│ 汐音          │ 舱面                               │ 汐音 · 开舱对话 │
│ 立绘 250      │  舱名（大字，可改）                 │  对话记录       │
│ 台词（引导）   │  目录 │ 注册表/仓库                 │  建议 3 条      │
│ 她记得        │  需求要点（可改回手写）              │  输入框         │
│ 快捷：上次目录 │  ─────────────────────────────    │                │
│ 舱≠任务/会话   │  没有下一步 / 说话即填写 / 一个闸门  │                │
│              │  创建后她会做的事（3 步）            │                │
├──────────────┴───────────────────────────────────┴────────────────┤
│ ● 草稿·还没有任何东西被创建        [保存草稿] [放下，先回对话] [开始创建 ⌘⏎] │
└──────────────────────────────────────────────────────────────────┘
```

- 舱面内容**垂直居中**（`margin:auto 0`，溢出时自动归零，不切头）；右侧对话独立滚动；
- **任何字段被填都不会改变其它元素的坐标**（沿用 v13 的布局铁律：只加边框/高亮，不加高度）；
- ≤1180 时对话收成右侧抽屉（「汐音 · 说话」浮动按钮打开），舱面不重排。

## 5. 字段映射（对着现有实现，不发明新概念）

| 舱面 | 原型 | 现有实现 | 说明 |
|---|---|---|---|
| 舱名 | `舱名` 大字输入 | `CreateCabinInput.name` | 只影响显示；目录才是身份 |
| 目录 | 虚线 chip + 小抽屉（她记得的 3 个 + 手动输入） | `path`（`browseDirectories` 弹窗） | 一目录 = 一舱 |
| 注册表 / 仓库 | org 固定 `XzhiF` + repo chips | `org` / `repos[]` | 可「不绑仓库」 |
| 需求要点 | `✦` 列表（可切手写） | `requirements` → `.cabin/requirements.md` | **要点是给人和给 agent 看的摘要**，落盘仍是正文 |
| 创建 | 三步进度 | `createCabin()` → `initCabin(id)` | 目录已有舱 → `attachCabin(path)` |

`attachCabin` 的语义在原型里就体现为：按钮文案从「开始创建」变成「**接进已有舱**」，面板明说"同一个目录不会有两个舱"。

## 6. 状态机

```
draft（默认）
 ├─ 说话 → 解析 → 字段命中（闪一下 + ✦ 来自对话）→ 仍 draft
 ├─ 手改舱面 → 仍 draft
 ├─ 保存草稿 → draft · 已保存在本地（chip 变实线绿）
 ├─ 缺目录 / 缺舱名 → 点开始创建 → 不发请求，她当场提醒 + 聚焦该字段
 ├─ 齐备 → 点开始创建 → creating
 └─ 目录已是舱 → 点开始创建 → attaching
creating：三步进度（落 .cabin/ → 接仓库 → 起主会话）｜可「停下」；停下 = 什么都没写
attaching：确认归属 → 打开已有主会话 → done（不新建）
done：chip「已创建」+ 面板「舱已就绪」+ 底部按钮变「进入作战舱 →」
```

**闸门的唯一性**（验收要卡的）：

- 页面打开 → 不发任何写请求（`GET` 也不必要）；
- 输入框里随便说多少句 → 只改本地 state；
- 「保存草稿」只写 `localStorage`（或舱外草稿目录），不建舱；
- 只有「开始创建 / ⌘⏎ / 说「开始创建」」→ 调用 `createCabin`。

## 7. 交互细则

| 事件 | 行为 |
|---|---|
| 说一句话 | 追加「你」气泡 → 她「思考」→ 解析 → 舱面命中字段闪一下 → 她回一句（带 `✦ 目录 …` 这类"我记下了"） |
| 她回话带缺项 | 缺目录 → 高亮目录 + 打开抽屉；缺舱名 → 聚焦舱名 |
| 舱面直接改 | 改哪个都行，改完仍要过同一个闸门 |
| 「改成手写」 | 要点列表 ⇄ 纯文本，两种形态都写进 `requirements` |
| 连说两句 | 后一句覆盖同名字段、合并仓库，不回滚已填内容 |
| `⌘⏎` | 开始创建（唯一闸门的键盘等价） |
| `⏎` / `⇧⏎` | 发送 / 换行（与舱内 composer 一致） |
| 停下 | 面板消失，状态回 draft，**已写的东西不动**（真实实现里要在写盘前拦） |
| reduced-motion | 立绘浮动 / 扫描 / 逐字全部关掉，直接出全文 |

## 8. 与现有实现的关系（迁移建议，不是本轮范围）

- `CabinDraftPane`（桌面内联）**基本就是这个方向**，已经不在弹窗里；差的是：没有汐音、没有"说话即填写"、没有闸门的可见性。
- 若采纳本稿：
  1. 把 `CabinNewForm` 的字段态提升成 `CabinDraftState`（name/path/org/repos/requirements + `source: 'talk' | 'manual'`）；
  2. 左栏复用 `CabinCrew` 的立绘与台词通道（同一份 `moodPortrait`，同一套 `say()` 语气）；
  3. 「说话即填写」需要一次 LLM 抽取（`{name?, path?, org?, repos?, requirements?}`），失败就退回纯手填，**不阻塞**；
  4. 「保存草稿」落 `localStorage['octopus.cabinDraft.v1']`；
  5. `createCabin` 冲突错误码 → 自动切 attach，按钮文案照原型改。
- 现有 `/cabin/new` 深链兜底页可继续渲染同一组件（整屏版）。

## 9. 验收（做实现时照这个验）

1. 打开开舱台：**没有任何弹窗**，一屏看到舱名 / 目录 / 仓库 / 需求 / 汐音 / 对话 / 底部闸门。
2. 说一句含目录 + 仓库 + 用途的话：三个字段被填上并各闪一次；需求要点里**不含"建舱/目录/仓库"这类指令词**。
3. 未点「开始创建」时：`POST /api/cabins` 计数 = 0；关掉页面后目录里没有 `.cabin/`。
4. 缺目录就点「开始创建」：**不发请求**，她说缺什么并把焦点送到那个字段。
5. 齐备后点「开始创建」：三步进度依次点亮；中途「停下」→ 无残留；跑完 → 「舱已就绪」+ 底栏变「进入作战舱」。
6. 已存在的目录：按钮变「接进已有舱」，点它不新建（`POST /attach`），面板文案说明"同一个目录不会有两个舱"。
7. 任何字段被填 / 被清空，其余元素 rect 不变（布局铁律）。
8. 读屏：立绘 `alt`、对话 `aria-live`、闸门按钮有 `aria-disabled` 而不是视觉禁用。

## 10. 遗留问题

- **立绘文件名与情绪不对应**（实测：`idle`=抬手指人、`alert`=托腮+问号、`thinking`=大笑、`wink`=全息键盘、`happy`=平静微笑、`working`=握拳眨眼、`worried`=眨眼比耶、`cheer`=睡着）。
  原型按**画面**挑图，`MOOD` 表里另取语义名；做实现时若继续用 `moodPortrait(mood)`，会出现"她在思考时是键盘打字图"这种错位 —— 要么重命名文件，要么加一层 `MOOD_ASSET` 映射。
- 「保存草稿」存哪：本地浏览器，还是 `.cabin/.draft.json`（跨机器可续）？后者会在"未创建"阶段就往目录里写东西，与闸门语义有冲突，建议先本地。
- 「说话即填写」是否要支持**改口**（"目录换成 X"）—— 原型已按"覆盖"实现，但多轮时要不要保留撤销？
- 草稿阶段要不要显示「这个目录里已有 .cabin/（不是本机注册的舱）」这种半残状态。
- 是否需要从开舱台一路直接进到全域座舱（跳过 classic），以及进去后第一句话由谁先开。
