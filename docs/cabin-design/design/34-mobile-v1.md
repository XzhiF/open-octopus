# 34 · 手机端 v1（原型）

> 状态：**原型定版**（2026-11-26），未实现 · 原型真源：`../mobile-v1.html`
> 落地计划：`35-mobile-dev-plan.md`；背景：`../../research/mobile-remote-control.md`（Qoder/WorkBuddy 调研、可达性方案、分阶段计划）
> 这版定**结构与规则**；技术选型（Flutter）与落地节奏见 35。

---

## 0. 结论先行

1. 手机上只做两件事：**进某个舱**，或者**开一个不归属任何舱的单独会话**。
2. **界面上不出现「改状态」的按钮** —— 待你定 / 待验收只是索引，点开回到会话，问题被引用进输入框，
   人用自然语言回答，由 agent 改状态。唯一例外：**「启动这台机器上的 Octopus」**（那一刻机器上没有 agent）。
3. 视觉**直接复用全舱模式素材**：`assets/scene-*.png` 底景 + v22 `#warp` 星流 canvas +
   13 支 VP9 alpha 透明立绘 `assets/v22/*.webm`；壳子用**圆角矩形**（卡片 18px / 按钮 16px + 药丸 /
   头像 12px 圆角方块），不做桌面的切角 + 六边形 —— 手机上柔一档。
4. 会话内容与桌面**同一份**：`❯` / `✦ 汐音 + meta` / `◌ thinking` / `▸ tool [✓]` / `✳ 正文`，换皮肤不换内容。

## 1. 目标 / 不做

| | |
|---|---|
| **目标** | 人在外面，能把家里那台机器上的活推进一格：看一眼有什么等你、说一句话、走了 |
| **不做** | 推送（见 §6）· App 内 VPN（手机系统里已有 Tailscale）· 多用户 / 账号体系 · 明细编辑（明细回桌面） |

## 2. 结构

```
设备列表（A）
 ├─ 添加设备（B · 扫码 / 手填 Tailscale 域名）
 └─ 选中设备
      ├─ 在线但没跑 → 远程拉起（C）
      └─ 运行中 → 设备首页（D）
            ├─ 新建单独会话（H）
            └─ 作业舱
                  └─ 舱内三块（E）：待你定 / 会话 / 任务
                        ├─ 会话（F · TUI 流）
                        └─ 待你定 → 回复（G · 引用条 + 同一份会话）
```

- **设备切换入口**在舱列表顶栏（点机器名回列表）。不做底部 tab —— 切设备不是高频动作。
- **舱内默认页 = 待你定**：打开手机是为了处理事情，不是为了翻日志。
- 三条状态：`运行中`（绿）/ `在线 · 未启动`（琥珀）/ `离线`（灰）。离线不能远程拉起。

## 3. 硬规则：状态由 agent 改，界面只带话

这条是 2026-11-26 用户明确纠正过的（第一版画了「通过 / 退回」按钮，被否）：

- ❌ 待办卡上不要「通过 / 退回 / 清掉 / 先不动」这类按钮。
- ✅ 列表项点开 = 回到**对应会话**，顶部挂一条引用（「正在回复：<那个问题>」+ 来源），
  输入框 placeholder 是「回复上面这个问题…」。
- ✅ 依据不另做面板 —— 它本来就在汐音那条消息里（`▸ Read … [✓]` / `▸ Grep … [✓ 5 处]`）。
- ✅ **唯一例外**：设备列表里的「启动」（以及未来的「停止」）。理由：按下那一刻机器上没有 agent。
- 与桌面 `tmp/chat-rows-v5-final.html` 的定调一致；同一条规则也写进了长期记忆
  （`ai-native-chat-one-summary-card`）。

### 4.1 立绘与动作（全舱模式同一套素材）

用户要的是「PC 全舱模式里那种全身立绘 + 动作」，所以不复刻、直接取现成素材：

- **素材**：`assets/v22/*.webm` 共 13 支，VP9 **alpha 透明底**（WebM `alpha_mode=1`，768×1152，
  人物高 1040 / 脚底 1105 / 中轴 384 已统一，切换不跳位）；顺序与 v22 一致
  （01-wink … 07-idle … 13-working）。
- **不需要遮罩**：video 自带 alpha，直接贴在 `scene-*.png` 上。静帧
  `crew/xiyin-*.png` 是**带背景的不透明图**，只用于头像和封面，不再做全身。
- **用法**：一屏最多 1 支在播 —— 设备列表 `07-idle` · 未启动 `05-concerned` · 空态 `09-smile`；
  点立绘按 13 支顺序换下一支（同 v22 的交互）。会话页不放全身，正文优先。
- **性能**：切后台暂停；`prefers-reduced-motion` 定格首帧；一屏别超 1–2 支（耗电 / 内存都在这）。
- **跨端注意**（实现时）：Android ExoPlayer 直接吃 VP9 WebM；iOS AVPlayer 不认 WebM，
  需要 HEVC-alpha 转码或静态帧兜底 —— 这是 Flutter 落地时要拍的一件小事，原型阶段不受影响。

## 5. 数据与接口（现状）

| 屏 | 读 / 写 | 端点 | 状态 |
|---|---|---|---|
| A 设备列表 | 运行状态 | `GET /api/actuator/health`（503=未就绪） | ✅ 已存在 |
| A · 在线未启动 | 需要进程外的探测 | sshd + `octopus-ctl` + 计划任务 | ❌ **未做**（调研稿 §5.9） |
| C 远程拉起 | 同上 | 同上 | ❌ 未做 |
| D 舱列表 | 舱 + 每舱待办数 | `GET /api/cabins`、`GET /api/cabins/:id/attention` | ✅ 已存在 |
| E 待你定 | 同上（`stage`: answer/start/review/adjudicate/approval/blocked） | 同上 | ✅ 已存在 |
| H 单独会话 | 建会话 | `POST /api/chat/global/sessions` | ✅ 已存在 |
| F/G 会话 | 发消息 / 流 | `POST /api/workspaces/:id/chat/sessions/:sid/messages`、SSE `GET /api/workspaces/:id/events` | ✅ 已存在 |

> 现在 server 只听 `127.0.0.1`，且**没有鉴权**。手机要连上，前面还有两道闸：
> ① 经 `tailscale serve` 把 47820 暴露到 tailnet（不绑 0.0.0.0）；② 最简单 token（可后置）。
> **绝不要**把 server 绑 `0.0.0.0` 或开公网隧道 —— 现有 API 能执行任意命令。

## 6. 技术选型与节奏

- **Flutter**（`packages/mobile/`，`flutter create --platforms=android,ios`）。理由：手机端只跟 HTTPS/SSE 打交道，
  不复用 `@octopus/shared` 的 Zod 模型；协议层手写 ~15 个端点的 Dart 模型即可。RN 的唯一优势（复用 schema）在这个体量下不值。
- **不做推送**：Android 自建 = 前台常驻服务（1–2 天 + 常驻通知 + 被 ROM 杀）；iOS 只能 APNs；
  真要做时最省的是自建 **ntfy**（Octopus POST 到 topic，手机装官方客户端，零推送代码）。
- **不做 App 内 VPN**：手机系统上已有 Tailscale，App 只认 `https://<机器>.<tailnet>.ts.net`。
- 落地顺序：**原型定稿 → `packages/mobile` 骨架 → 先连局域网裸调 → 再补 token**。
