## 0. 用户原话（2026-11-15，逐字）

> 还可以吧，不过我是希望说我新建一些。我左边的话预先有一个仓，反正给个默认名字也行吧。然后右边 tab 就是你这个窗口的内容，你现在大致的给我说明一下，因为我不想那种全局模态的话，就是感觉必须操作似的，有时候我没想好，我其实也可以取消的嘛是吧就是行政任务时的那种逻辑再给我稍微设计一下吧

**读法**：「行政任务」= **新建任务**。要的不是界面本身，是**它怎么待在壳里** —— 左栏预先有一行、右边是一页可关的页、不挡路、随时能取消。

## 1. 结论：不接管屏幕，占「一行 + 一页」

```
┌────────── 左栏（不动） ──────────┬──────────── 右页 ────────────┐
│ Octopus                    ⚙ ＋  │  ▣ 新建作战舱 ●草稿      ×   │
│ [✎ 开启新对话 ▾]                │  不会创建任何东西，直到开始创建 │
│                                 ├──────────────────────────────┤
│ 作战舱 3                    ＋   │        [汐音] 选个目录…        │
│ ● 未命名舱          草稿中  ×    │        ┌──────────────┐        │
│ ▣ 八爪舱              就绪       │        │ 目录          │        │
│ ▣ 账本舱            运行中       │        │ 舱名 / ☐☐     │        │
│                                 │        │ [开始创建]     │        │
│ 任务 2                          │        └──────────────┘        │
│ 会话 3                          │                                │
└─────────────────────────────────┴───────────────────────────────┘
```

两条硬约束：

1. **左栏永远在**。新建不是模态，不盖住任何东西，不锁滚动，不逼你先做完。
2. **右边只是一页**，跟一个舱、一条会话同级别：可切走、可关闭。

## 2. 左栏那一行：跟「新建任务」同一套

现有「任务」段已经有一个 `pendingTask` 行（`chat-sidebar.tsx:581`，呼吸点 + 「草稿中」）。作战舱照抄它：

| | 任务（已有） | 作战舱（本稿） |
|---|---|---|
| 行出现时机 | 点「新建开发任务」 | 点「新建作战舱」 |
| 左边 | 青色呼吸点（`animate-ping`） | 同 |
| 名字 | 待命名任务标题 | **`未命名舱`**，跟着舱名/目录实时变 |
| 右边 | 「草稿中」 | 「草稿中」 |
| 悬停 | — | 出现 `×`（丢弃草稿） |
| 计数 | `count` + 1 | `count` + 1 |

**默认名字规则**（就是"给个默认名字也行"）：`输入框里的名字 → 目录名 → 未命名舱`。三者任一变化，左栏那一行、右页 tab、完成态标题同时变 —— 你不用为了"有个名字"先想。

## 3. 右页：一个 tab 头 + 四个视图

tab 头（高 44，跟壳里其它头一致）：`▣ 名字 · 状态chip · ×`，右边一句随时更新的说明。

| 视图 | 触发 | 头 |
|---|---|---|
| 草稿 | 点左栏草稿行 / ＋ | `新建作战舱 · 草稿`，有 `×`，说明「不会创建任何东西，直到 **开始创建**」 |
| 完成 | 创建成功 | `极光舱 · 已创建`，无 `×`，说明「会话已开 · 初始化在**舱内对话**里」 |
| 舱内 | 点任一舱行 / 「进入作战舱」 | `账本舱 · 舱`，说明「一个目录 = 一个舱」 |
| 空态 | 取消草稿之后 | `对话 · —`，说明「什么都没建 —— 取消是安全的」 |

草稿视图就是 v2 那张卡：小像 + 两句 + 目录 / 舱名 / 两个勾选 / 一个「开始创建」。尺寸压到 pane 里（卡 548 宽，行高 54/44/38）。

## 4. 三条退路（这是本次的重点）

"我不想那种必须操作的模态"= 每一条退路都要便宜、可逆、不用确认。

| 退路 | 怎么走 | 留下的东西 | 是不是安全 |
|---|---|---|---|
| **走开** | 点左栏任一舱 / 任务 / 会话 | 草稿行留着（`草稿中` + 呼吸点），回来点它接着填，**已填的都在** | 安全：零请求 |
| **放一放** | 卡片左下「先放一放 · 草稿留着」 | 同上，只是主动去舱里干活 | 安全：零请求 |
| **取消** | tab 头 `×` 或草稿行悬停 `×` | 什么都不留，右页回空态；左栏计数 -1 | 安全：本来就没建过 |

**没有二次确认**：因为闸门只有一个，`×` 之前确实什么都没发生（不建目录、不落库、不接仓库）。这就是"没有负担"的来源。

> 刻意不做：离开时弹「要保存草稿吗？」。弹窗正是用户不想被逼的那种东西。

## 5. 状态与闸门（没变的部分）

```
左栏草稿行 ─┬─ 走开 / 放一放 → draftKept = true（右页换视图，草稿不动）
            ├─ 取消 → draftAlive = false（右页空态）
            └─ 开始创建 → 真的建 → 草稿行换成正式舱行（就绪）→ 右页完成态 → 进入舱
```

- 「开始创建」仍是**唯一的写操作**；`⌘⏎` 等价。
- 目录已是舱 → 按钮变「接进「X舱」」，完成后 tab 与完成态都写"已接入"。
- 取消后再新建 → 全新空草稿（原型如此；真实实现可考虑"上次没建的那份还在不在"）。

## 6. 接进现有代码（很小，因为骨架已经在了）

`components/cabin/cabin-mode.tsx` 里**已经有** `drafting / startDraft / cancelDraft`；`ChatTab` 已把 `drafting` 传进 `CabinDraftPane`。缺的只有三件：

1. **左栏加草稿行**（`components/agent/chat/chat-sidebar.tsx`）
   新增 `pendingCabin?: { name: string } | null`，渲染在 `cabin-section` 的第一行，样式直接复用 `pending-task-item`（`:581` 那段）——同一个呼吸点、同一个「草稿中」。计数 `+1`。
2. **草稿态要能活过"走开"**（`cabin-mode.tsx`）
   现在 `openCabin()` 里 `setDrafting(false)`，一走开草稿就没了。改成两个概念：
   - `draft: CabinDraftState | null`（字段：name/path/org/repos/requirements，**不随视图销毁**）
   - `draftOpen: boolean`（右页当前是不是草稿视图）
   `openCabin/exitCabin` 只动 `draftOpen`；`cancelDraft()` 才把 `draft` 置 null。
3. **字段态从 `CabinNewForm` 提到壳里**（`CabinNewForm.tsx` → 受控）
   v2 的五条落地建议（`design/15` §8）不变：名称可空、两个可选项默认收起、不在此处渲染 init 进度、attach 分支保留。

右页 tab 头可以直接放在 `CabinDraftPane` 外层（现在它是"对话区整块替换"，加一条 44px 的头不影响布局）。

## 7. 验收

1. 打开就有：左栏「作战舱」第一行是 `● 未命名舱 草稿中`，右页是草稿卡，**没有任何遮罩/模态**。
2. 输入舱名 → 左栏行、tab 名同步变；清空 → 回落「未命名舱」；选了目录 → 回落目录名。
3. 点另一个舱 → 右页切舱，草稿行还在；点草稿行 → 字段全在；舱内顶部有「你还有一份草稿 … 接着填 →」。
4. 点「先放一放」→ 同上，但去舱里。
5. `×` → 草稿行消失、计数 -1、右页空态；`POST /api/cabins` 计数 = 0；目录里没有 `.cabin/`。
6. 「开始创建」→ 草稿行变正式行（就绪）、tab 变「X舱 · 已创建」、完成态同高不跳。
7. 「进入作战舱」→ 舱内视图，汐音第一句就在问"这个舱长期拿它做什么"（对应 init 门禁 7 的 agent 回合）。
8. 窄屏 ≤640：左栏收起，右页仍然是一页（可关、可取消）。

- 刷新页面：草稿存 `localStorage['octopus.cabinDraft.v1']` 还是丢弃？建议存，键里带 `updatedAt`，超过一天就丢。
- 关闭右页（`×`）之后，是否回到"上一次看的东西"而不是空态？空态更诚实，但多一次点击。
