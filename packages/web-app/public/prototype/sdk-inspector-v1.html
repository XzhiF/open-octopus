决定 只放作业坞「调试」

对话区保持纯净转录，不加入口；调试是窗口级工具，和「消耗 / 运行」同层。

入口 = 作业坞的第四格（文件 / 活动 / 消耗 / 调试）。琥珀徽标显示异常轮数，绿点表示正在记录，⌘⇧D 作为键盘兜底。

01 多轮：先看到最新，再按需往回

  • 默认最新：打开窗口直接落在 T32（最新一轮），列表倒序；12 / 32 / 80 轮都一样。
  • 轮次尺：顶部一根 tick 代表一轮，颜色 = 身份（主 Agent 粉 / 前端专家紫 / 代码评审员青），底部横线 = 异常；点任意 tick 直达该轮，旧轮自动展开并滚到该行。80 轮仍能一屏放下。
  • 折叠：默认只展开最近 10 轮；更早的收成「显示更早的 22 轮」。过滤态显示全部匹配项，不做二次折叠。
  • 过滤：全部 / 切换 / 异常，带实时计数；切换过滤时若当前轮不匹配，自动跳到第一个匹配轮。
  • 回顶：列表右上「↑ 最新」一键回到最新轮；滚到旧轮后不用手动找。
  • 密度：两行约 36px，一屏约 13 行；≤100 轮不需要虚拟列表，再大再上窗口化。

顶部控制条可直接切 12 / 32 / 80 轮验证；轮次尺与列表同步。

02 五个页签各回答什么

  • 概览：这一轮值不值得细看——耗时、首 token、token 拆分、成本、上下文占比、停止原因、身份 revision。
  • Prompt：用户消息「原始 vs 实际发送」；system prompt = SDK preset（claude_code，不可见全文）+ append 片段栈；每段预算/截断/冻结快照；SDK 运行时回报的分段 token。
  • 身份：切换前后 diff（persona / SKILL / memory / cwd / agents / MCP）、role revision、岗位包全文；解释「为什么 system prompt 没变」。
  • SDK：实际 sendQuery options 快照、agents 名册、MCP server/tools、system tools、skills、slash commands、raw JSON。
  • 时间线：subprocess 启动 → init → message_start → 工具 → result，每步毫秒偏移；中止轮标 interrupt() 与带用量的 error result。

03 为什么只放坞是成立的

  • 对话区是转录，不该承担窗口级工具；坞已有「消耗 / 运行」这类读数，调试与它们同层。
  • 没有逐消息角标，消息 meta 行保持原样，转录更安静。
  • 深链仍保留：身份切换卡上的「在调试中查看岗位包」把窗口定位到对应轮的身份页签；它不是调试入口，只是上下文跳转。

实现落点：TaskModule 增加 'debug'，复用 TaskWindow 的拖动 / 最小化 / 几何持久化；本原型只画内容层。

落实现前必须解决：现有 WorkspaceExplorerDock 在 !workspaceId 时直接 return null，纯会话会没有坞、也就没有调试入口。两个选项：① 坞在纯会话也挂载（只显示 文件 / 活动 / 消耗 / 调试）；② 保留 ⌘⇧D 与窗口菜单的兜底入口。原型按 ① 展示。

04 后端：已经有的，和缺的

已具备

  • session_prompt_snapshots 存了本会话冻结的 system_prompt + hash。
  • SDK 每轮 getContextUsage() 已返回 systemPromptSections / systemTools / mcpTools / agents / memoryFiles / slashCommands。
  • role-switch 消息 metadata 里有 role_revision 和整张岗位包 card。
  • llm_calls 账本有逐轮用量与 stopReason，可还原 token / 成本 / 中断。
缺口
① GET /api/agent/debug/assemble/:chat_id 现在是占位实现：忽略 chat_id、重拼通用片段、system_prompt 返回空串；要改成按 session 读冻结快照。
② 实际发送的 provider message 没有持久化：withTransientReminder() 拼上角色卡/委派提醒后只进 SDK；需要按轮落 providerMessage + options。
③ SDK system:init 多数字段被丢弃（provider 只消费 slash_commands）：工具、MCP 状态、permissionMode、skills 要抓下来。
④ sessions.context_usage 是单列覆盖写，只能看最新轮；逐轮上下文要在新表/JSONL 里存快照。

05 降噪与保留

  • 默认记录跟随设置；原型用顶部 REC 开关演示。关闭后不新增快照，历史轮仍可看。
  • Prompt 全文默认折叠；敏感值打码（API key / token / 绝对路径可脱敏），复制只走本地剪贴板。
  • 建议保留：7 天 / 每会话最近 50 轮，可导出 JSON；Prompt 全文单独开关。
  • 80 轮的压力点不在列表渲染，而在落盘：JSONL 按轮追加，列表接口只读摘要（id / 时间 / 身份 / 状态 / 用量），详情按轮懒加载，别把整包 prompt 塞进列表。

07 参考：DeepSeek Harness 生态怎么拆

DSH 本体（deepseek-ai/deepseek-harness）是 developer preview，官方文档没有单列「prompt 检查器 / Trajectory」页面；真正可参考的是社区插件把这件事拆成了四层：

  • 请求载荷 — dsh-payload-capture 把上游模型 API 的 payload 落盘，专门调试「请求怎么拼出来的」。
  • 上下文账本 — dsh-context 按请求拆 System Prompt / tool schemas / messages / injections / replies / tool results 的 token，并标记 compaction、pruning、cache hit。
  • 调用轨迹 — LoongSuite / 腾讯云 Agent Observability 把 Agent Turn、模型调用、工具执行、Token 使用转成 OpenTelemetry GenAI trace。
  • 会话回放 — token-monitor 按回合展示 Prompt、工具记录与 token；dsh-session-surgeon 检查/导出/修复会话。

这四层正好对应本原型的 Prompt / 概览 / 时间线 / 作业坞轨迹；我们额外补的一层是身份角色卡与 system prompt 冻结快照——这是 Octopus 的多分身架构特有的，DSH 生态里没有对应物。
