💡 改了什么？

十一个改动点的原型答案（点卡片进弹窗体验）

① 执行中即可看变更 — 弹窗默认页签「变更」：提交数 + 文件 +/− 统计条，GitHub 式文件列表，点行就地展开 unified diff。数据即现有 /round-diff?scope=round|cumulative，不用新后端。
② 待验收 · 快速修改对话 — 像草稿一样对话改代码，改动实时进「变更」列表（💬chat 徽标）与统计。说大改动（含「重构/批量/接口…」）→ chat 主动引导转打回（task-fix 修复轮）。简单直接 chat，复杂派轻流。
③ 两个弹窗合一 — 执行中/待验收同一个壳：顶栏只留 标题+状态+时间成本（8 个动作按钮收进右栏底部），差异只剩右栏（进度 vs 验收动作）与一个页签。字号 10→11.5px、行距加大，砍掉嵌套卡片。
④ 执行中 · 「节点」页签 — 工作流节点执行情况做成任务清单：✓/●/⏸/○ 状态 + 节点类型徽标（Agent/Bash/Loop/Swarm/Approval）+ 用时成本，点行展开该节点事件。对齐引擎现有节点事件流。
⑤ 暂停 → 干预 → 恢复 — 右栏「⏸ 暂停」挂起当前节点；再点「▶ 恢复」弹出干预注入框：写的干预信息以粉色高亮行（⚑ 人工干预）进控制台、进当前节点事件，并作为额外上下文交给该节点 — 和工作流节点的人工干预同一语义。留空 = 原样继续。
⑥ chat = 整屏页签 — 待验收打开即「💬 对话」（与执行中的「💬 对话接管」同款整屏，直接干活，改动实时进「变更」页签）；右栏只做验收进度 + 决断（通过/打回），不放对话按钮。执行中默认不打扰：干预走「⏸→注入」或「✋ 有问题」①；task-fix 期间底部 dock 接追加干预。
⑦ 执行中「✋ 有问题」三分支 — 右栏新入口，一次选择本 Round 的去向：① 注入干预原流继续；② 停流接管：打开草稿同款整屏「💬 对话接管」页签，每句直接动工作区，交付/改派只在右栏一处；③ 派通用 task-fix：给指令，自动 开发→回归→调整→补产物(报告/证据)→自动转待验收。接管件/修复件在验收台会被标出来。
⑧ 启动 Runbook 落点 — 「走查」页签第一块：📜 启动 Runbook（spec 字段 startup_runbook · 入队硬闸校验过），N 步「命令 → 预期」，每步带「▶ 跑」；右栏有「已预设 · N 步 ▸」入口。验收 = 照单跑实物。
⑨ 打回语义收敛 — 去掉「修订重跑绑定流」选项：打回 = 派 task-fix 轻轮修复（反馈即指令，开发→回归→补产物→自动回待验收 R+1），与「✋ 有问题」③ 同一机制。方向要整体推翻 → 用 ② 接管，不再靠重跑。
⑩ 真机走查回补：删残留右栏 · 日志归位 · 消耗/产物独立页签 — 真机发现旧弹窗残留三处：一 走查里内嵌的「摘要+动作 / 验收进度」右栏整体删掉（最右栏已有同款），其中的「■ 中止」挪到最右栏「打回」下方成为唯一入口；二「▶ 控制台/日志」应播工作区运行日志（SSE 事件流），不是现在错位的「任务 AI 消耗」；三 新增两个页签：▤ 消耗（完整 token 账 — token 用 K/M 记数，三段式：总计（∑处理量 ↑输入 ↓输出 ⚡缓存读 🗡️缓存写 ·请求数 ·成本）、按模型、分轮账本（⇕ 一键全展开/收起），底部再按会话/节点分列明细表，task-doer 对话单独一行、两账不混）与 ▣ 产物（spec/票/报告/证据/台账等交付文件清单，区别于「≡ 变更」的 diff 视图）。
⑪ 真机复点收口 — 「✓ 走查」「▶ 日志」页签背景与壳同框净黑（去掉内嵌亮卡片衬底）；日志流铺到底、新事件自动贴底；待验收最右栏四钮定版 = ✓ 验收通过（绿）→ ↩ 反馈打回（粉底，不再素面）→ 🗂 工作空间（青，当前 Phase 执行视图深链，target=_blank 新标签）→ ■ 中止任务（红底）；中止必过二次确认框（红字后果说明 + 取消/确认中止），执行中与接管态的「■ 中止」同框同流。
试试：待验收卡 → 默认落在「💬 对话」，说「验收通过按钮再圆一点」看改动进「变更」；「✓ 走查」页签顶部看 Runbook；执行中卡 → 「✋ 有问题」选②/③ 各走一遍；⏸ 暂停后「▶ 恢复」体验注入干预。←/→ 切页签。
