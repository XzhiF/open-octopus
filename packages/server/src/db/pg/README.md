# `db/pg/` — Postgres（ParadeDB）单引擎地基 · P1

SQLite `schema.sql`（SCHEMA_VERSION 49）的 PG 平移面。**本目录只做「库的形状」**：
DDL、迁移器、驱动接线、比对测试。DAO 异步化是下一票，今天所有读写仍走 SQLite。

## 文件地图

| 文件 | 职责 |
|---|---|
| `schema.sql` | 42 表 + 102 索引 + 3 FTS 占位表 + 6 触发器的 PG DDL（幂等重放式，全 `IF NOT EXISTS` / `CREATE OR REPLACE` / `ON CONFLICT DO NOTHING`） |
| `migrate.ts` | `applyPgSchema()` —— 全量重放 + IDENTITY `setval` 同步 + `octopus_schema_version` stamp（等价 `user_version`） |
| `config.ts` | 环境变量 → `PgPoolConfig`（池上限/查询级超时全可配） |
| `pool.ts` | postgres.js 池 + 查询计数 + `getPgPoolStats()`（pg_stat_activity 占用 + 排队估算） |
| `__tests__/harness.ts` | 随机测试库 lifecycle（见下） |
| `__tests__/schema-parity.test.ts` | 逐表逐列 SQLite↔PG 比对（映射规则表在测试文件头部显式编码） |
| `__tests__/migrator-idempotency.test.ts` | 同一库重放两遍，逐对象快照相等 |
| `__tests__/live-octopus-migrate.test.ts` | 对真库跑重放的显式 opt-in 入口（默认永不执行） |
| `__tests__/pool.test.ts` `config.test.ts` | 接线面单测（超时落会话 / 计数 / 脱敏） |

## 跑测试

```bash
# 无 PG 时：全部 pg 测试 skip 并打一行警告（CI 无 PG service，勿改 workflow —— 另票加）
pnpm --filter @octopus/server test

# 有 PG（本机 deploy/docker-compose.pg.yml 已起）：
OCTOPUS_PG_TEST_URL=postgres://octopus:octopus@127.0.0.1:5432/octopus \
  pnpm --filter @octopus/server test src/db/pg

# 活体幂等验证（对 OCTOPUS_PG_URL 指向的真库连跑两遍迁移器，需要双确认）：
OCTOPUS_PG_LIVE_MIGRATE=yes OCTOPUS_PG_URL=postgres://octopus:octopus@127.0.0.1:5432/octopus \
  pnpm --filter @octopus/server test src/db/pg/__tests__/live-octopus-migrate.test.ts
```

`OCTOPUS_PG_TEST_URL` 要求实例里有 `octopus_template` 库（deploy/pg-init/01-extensions.sql
随容器首建自动创建，携带 vector/pg_search/pg_stat_statements 扩展）。

## 测试 harness 用法（交付物 5）

```ts
import { pgTestEnabled, createTestDatabase, type PgTestDatabase } from './harness'

const describePg = pgTestEnabled ? describe : describe.skip

describePg('…', () => {
  let db: PgTestDatabase
  beforeEach(async () => { db = await createTestDatabase() })   // CREATE DATABASE 随机名 TEMPLATE octopus_template + applyPgSchema
  afterEach(async () => { await db.close() })                   // end 池 + DROP DATABASE ... WITH (FORCE)
})
```

护栏：库名恒为 `octopus_test_<12hex>`，`close()` 里正则不过就拒绝 DROP —— 代码层面
不可能删到 `octopus` / `octopus_template`。

## 存量 88 个 `:memory:` 测试怎么逐批切过来（下一票的施工图）

1. **形态映射**：`new Database(':memory:') + applySchema` →
   `const { sql } = await createTestDatabase()`。用例内 `stmt.run/get/all` 逐条改 `await sql`…``。
2. **隔离策略分层**（按成本挑，不要一刀切）：
   - *快路径（推荐）*：harness 的 `octopus_template` 灌好 schema 后建库毫秒级；
     每例一座库，afterEach DROP。并发跑互不污染，单例可独立跑（判据要求）。
   - *省路径（写密集型大套件）*：全文件共享一座库 + 每例 `BEGIN … ROLLBACK`：
     `const tx = await db.sql.begin(async tx => …)` 内跑断言、结尾刻意 `tx.rollback()`
     （postgres.js begin 的回调抛错即回滚；不抛时改 `await tx`+显式回滚需
     `sql.begin` 外包 `Promise.reject(ROLLBACK_SENTINEL)` 或 TRUNCATE 兜底）。
     兜底清单：`scheduled_job_executions, llm_calls, agent_events, executions,
     node_executions …` 按 FK 逆序 TRUNCATE，供无法回滚的场景（触发器断言类用例）。
   - *模板升级*：把 `createTestDatabase()` 默认 `migrate:true` 切到「template 已含
     schema 时跳过迁移」（`{ migrate: false }`），建库降到 ~10ms 级。
3. **不要迁移的东西**：`PRAGMA foreign_keys`（PG 常开）、WAL/busy_timeout 系
   （整类删除，62 处 PRAGMA 属 SQLite 方言）。
4. **布尔翻面**是本票类型映射最大的静默风险（0/1→bool）：DAO 切过来时
   `row.done === 1` 全量改 `row.done === true`，tsc ratchet 抓声明、抓不到
   `as number` 强转 —— 每批只动一个 DAO 目录，全量测试绿且用例数不降再下一批。

## 本票边界（遗留给下一票的接口点）

- **打包态读取**：`migrate.ts` 的 `readPgSchemaSql()` 先试 `dist/pg/schema.sql` 再试
  同级 `schema.sql`，并有 PG 方言标记校验（读到 SQLite 那份会抛错）。DAO 异步票把
  `applyPgSchema` 接进 `node dist/index.js` 启动路径时，需在 `tsup.config.ts` 的
  `onSuccess` 里照 SQLite 那份加一条 `src/db/pg/schema.sql → dist/pg/schema.sql`
  拷贝（本票不接启动路径，刻意未动 tsup）。
- **pg_search BM25**：`session_memory_fts` / `experiences_fts` / `reports_fts` 现在是
  普通占位表（无消费者、无同步触发器 —— `messages_after_*` 两个触发器判定为删，
  理由写在 `schema.sql` Triggers 段）。pg_search 票把索引直接建在 messages/experiences/
  reports 真表上，占位表届时 DROP；FTS5 的 27 处 `MATCH` 改写在那一票做。
- **DAO 异步票**：`pool.ts` 已备好注册面（`initPgPool`/`registerPgPool`/`getPgPoolStats`）；
  `schema-parity.test.ts` 里的 `JSONB`/`BOOL`/`EPOCH_MS`/`IDENTITY` 四张映射表就是 DAO
  行类型的施工图 —— 表里列的列，DAO Row 接口必须同步改成 `object`/`boolean`/`string(bigint)`。
- **账本三件套**：`llm_calls_costed` 视图（price-sql.ts）是 SQLite SQL 方言，平移属
  账本票，本票刻意未建。
- **数据搬迁**：`IDENTITY` 用 `GENERATED BY DEFAULT` + migrate 每次 `setval`，
  就是为了 COPY 带原 id 后重启自动对齐；搬迁时 `SET timezone='UTC'`（无标记串坑）。
